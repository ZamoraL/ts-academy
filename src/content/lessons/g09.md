React decide si volver a renderizar comparando el estado nuevo con el anterior **por referencia** (`Object.is`). Por eso, con objetos y arrays, **nunca los mutes**: crea uno nuevo.

## Objetos

```jsx
const [persona, setPersona] = useState({ nombre: 'Ada', ciudad: 'Londres' })

// ❌ muta: es el mismo objeto, React no se entera
persona.ciudad = 'París'
setPersona(persona)

// ✅ objeto nuevo con spread
setPersona({ ...persona, ciudad: 'París' })
```

### Anidados

Hay que copiar cada nivel que cambia:

```jsx
setPersona({
  ...persona,
  direccion: { ...persona.direccion, cp: '75001' },
})
```

Si el anidamiento es muy profundo, quizá el estado debería tener otra forma.

## Arrays

Todo lo que aprendiste sobre no mutar en el bloque A cobra sentido aquí:

| Quiero | ❌ Muta | ✅ Nuevo array |
|---|---|---|
| Añadir | `push`, `unshift` | `[...arr, item]`, `[item, ...arr]` |
| Quitar | `splice`, `pop` | `arr.filter((x) => x.id !== id)` |
| Reemplazar | `arr[i] = x` | `arr.map((x) => (x.id === id ? nuevo : x))` |
| Ordenar | `sort`, `reverse` | `arr.toSorted()`, `[...arr].sort()` |

```jsx
const [tareas, setTareas] = useState([])

function agregar(titulo) {
  setTareas([...tareas, { id: Date.now(), titulo, hecha: false }])
}

function alternar(id) {
  setTareas(tareas.map((t) => (t.id === id ? { ...t, hecha: !t.hecha } : t)))
}

function borrar(id) {
  setTareas(tareas.filter((t) => t.id !== id))
}
```

Exactamente las funciones de tu proyecto del bloque A, ahora conectadas a una interfaz.

## Con la función actualizadora

Si varios cambios pueden ocurrir seguidos, usa la forma con función:

```jsx
setTareas((prev) => [...prev, nueva])
```

## Estado mínimo

No guardes en el estado lo que puedes **calcular**:

```jsx
// ❌ dos estados que hay que mantener sincronizados
const [tareas, setTareas] = useState([])
const [pendientes, setPendientes] = useState(0)

// ✅ se calcula en cada render
const pendientes = tareas.filter((t) => !t.hecha).length
```
