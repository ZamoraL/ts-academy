`fetch` hace peticiones HTTP desde el navegador. Es la forma estándar de hablar con APIs.

## GET básico

```js
const respuesta = await fetch('https://api.example.com/usuarios/1')
const usuario = await respuesta.json()
```

Dos `await`: el primero espera a que lleguen **las cabeceras**, el segundo a que llegue y se lea **el cuerpo**.

## La trampa: fetch no falla con 404 o 500

`fetch` solo rechaza la promesa por errores de **red** (sin conexión, DNS...). Una respuesta 404 o 500 **se cumple** normalmente. Tienes que comprobar `ok`:

```js
const r = await fetch(url)
if (!r.ok) {
  throw new Error(`HTTP ${r.status}`)
}
const datos = await r.json()
```

- `r.ok`: `true` si el status está entre 200 y 299.
- `r.status`: el código (200, 404, 500...).

## POST con JSON

```js
const r = await fetch('https://api.example.com/tareas', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ titulo: 'Aprender fetch' }),
})
const creada = await r.json()
```

Otros métodos: `PUT`, `PATCH`, `DELETE`.

## Parámetros de búsqueda

```js
const params = new URLSearchParams({ q: 'typescript', pagina: '2' })
fetch(`https://api.example.com/buscar?${params}`)
// .../buscar?q=typescript&pagina=2
```

## Una función reutilizable

```js
async function getJSON(url) {
  const r = await fetch(url)
  if (!r.ok) throw new Error(`HTTP ${r.status}`)
  return r.json()
}
```

## En los ejercicios

Los ejercicios no usan internet: los tests **reemplazan `fetch`** por una versión falsa que devuelve datos de prueba. Tu código debe llamar a `fetch` normalmente.
