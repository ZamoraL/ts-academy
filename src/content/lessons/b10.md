JavaScript ejecuta **una sola cosa a la vez** (un solo hilo). Entonces, ¿cómo espera a una red lenta sin congelar la página? Con el **event loop**.

## Código síncrono

```js
console.log('A')
console.log('B')
console.log('C')
// A, B, C
```

## setTimeout: programar para después

```js
console.log('A')
setTimeout(() => console.log('B'), 1000)
console.log('C')
// A, C ... (1 s después) B
```

`setTimeout` no pausa el programa. Registra la función y **sigue**.

## Incluso con 0 ms

```js
console.log('A')
setTimeout(() => console.log('B'), 0)
console.log('C')
// A, C, B
```

## Cómo funciona

1. JavaScript ejecuta todo el código síncrono actual (la **pila**).
2. Las tareas listas (timers vencidos, respuestas de red, clics) esperan en una **cola**.
3. Cuando la pila se vacía, el event loop toma la siguiente tarea de la cola y la ejecuta.

Por eso un callback **nunca** interrumpe código que se está ejecutando, y un bucle muy largo congela la página: nada de la cola puede correr.

## Callbacks

Un **callback** es una función que pasas para que se llame más tarde:

```js
function cargarDatos(alTerminar) {
  setTimeout(() => {
    alTerminar({ nombre: 'Ada' })
  }, 500)
}

cargarDatos((datos) => console.log(datos.nombre))
```

## El problema: callback hell

Encadenar operaciones asíncronas con callbacks se vuelve ilegible:

```js
login(user, (sesion) => {
  cargarPerfil(sesion, (perfil) => {
    cargarAmigos(perfil, (amigos) => {
      // ...
    })
  })
})
```
