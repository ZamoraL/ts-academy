Tu cliente de la parte 1 hace una petición cada vez que lo llamas, y falla a la primera. Vamos a hacerlo más robusto.

## 1. Caché

Si pides el mismo usuario dos veces, la segunda no debería llamar a la red.

Implementa `conCache(fn)`: recibe una función async de un argumento y devuelve **otra función** que guarda los resultados en un `Map` por argumento.

```js
const usuarioCacheado = conCache(cliente.usuario)
await usuarioCacheado(1) // fetch
await usuarioCacheado(1) // desde la caché, sin fetch
```

**Detalle importante:** guarda la **promesa**, no el resultado. Así, si se hacen dos llamadas a la vez antes de que termine la primera, ambas comparten la misma petición. Si la promesa falla, bórrala de la caché para poder reintentar.

## 2. Reintentos

Implementa `conReintentos(fn, intentos)`: devuelve una función que llama a `fn` y, si lanza un error, lo vuelve a intentar hasta `intentos` veces **en total**. Si todas fallan, lanza el último error.

```js
const robusto = conReintentos(() => getJSON(url), 3)
```

## 3. Timeout

Implementa `conTimeout(promesa, ms)`: devuelve una promesa que se resuelve como `promesa`, pero si tarda más de `ms`, se rechaza con `Error('Timeout')`.

Pista: `Promise.race` con una promesa que se rechaza tras un `setTimeout`.

## Lo que estás practicando

Closures (la caché vive dentro de la función devuelta), funciones de orden superior, `Map`, promesas, `async/await`, `try/catch` y `Promise.race`. Son patrones reales que verás en librerías como React Query.
