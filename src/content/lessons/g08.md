Una variable normal no sirve para datos que cambian:

```jsx
function Contador() {
  let n = 0
  return <button onClick={() => n++}>Clics: {n}</button> // siempre muestra 0
}
```

1. Las variables locales no sobreviven entre renders: cada llamada a `Contador` empieza con `n = 0`.
2. Cambiar una variable local **no avisa a React** de que tiene que volver a renderizar.

## useState

`useState` resuelve las dos cosas:

```jsx
import { useState } from 'react'

function Contador() {
  const [n, setN] = useState(0)
  return <button onClick={() => setN(n + 1)}>Clics: {n}</button>
}
```

- `useState(0)`: declara un estado con valor inicial `0`.
- Devuelve un par (una tupla, ¿recuerdas?): el **valor actual** y una **función para cambiarlo**.
- Al llamar a `setN`, React guarda el valor nuevo y **vuelve a renderizar** el componente.

## Hooks

Las funciones que empiezan por `use` se llaman **hooks**. Reglas:

- Solo se llaman **en el nivel superior** de un componente (no dentro de `if`, bucles o funciones anidadas).
- Solo desde componentes o desde otros hooks.

React identifica cada estado por **el orden** en que llamas a los hooks; por eso no pueden ser condicionales.

## Varios estados

```jsx
const [nombre, setNombre] = useState('')
const [edad, setEdad] = useState(0)
const [abierto, setAbierto] = useState(false)
```

## El estado es local y privado

Si renderizas `<Contador />` dos veces, cada uno tiene **su propio** `n`.

## El estado es una "foto"

Dentro de un render, `n` no cambia aunque llames a `setN`:

```jsx
function manejarClic() {
  setN(n + 1)
  setN(n + 1)
  setN(n + 1)
  // n sigue siendo el mismo en este render: el resultado es +1, no +3
}
```

Si el nuevo valor depende del anterior, pasa una **función actualizadora**:

```jsx
setN((anterior) => anterior + 1)
setN((anterior) => anterior + 1)
setN((anterior) => anterior + 1) // +3 ✅
```

Recuerda los closures del bloque B: cada render "captura" su propio `n`.
