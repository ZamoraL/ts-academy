## El problema

Al compilar, TS borra los imports que solo traen tipos. Pero para saberlo, tiene que analizar el otro archivo. Herramientas como Vite o esbuild compilan **archivo por archivo**, sin mirar los demás, así que no pueden saber si `Usuario` es un tipo o un valor:

```ts
import { Usuario, crearUsuario } from './usuarios'
// ¿Usuario es una interface (borrar) o una clase (conservar)?
```

## import type

Marca explícitamente lo que es solo tipo:

```ts
import type { Usuario } from './usuarios'
import { crearUsuario } from './usuarios'

// o en una sola línea
import { crearUsuario, type Usuario } from './usuarios'
```

Ahora cualquier herramienta sabe que `Usuario` se borra sin mirar `usuarios.ts`.

Lo mismo al exportar:

```ts
export type { Usuario } from './usuarios'
```

## verbatimModuleSyntax

Esta opción de tsconfig (TS 5.0+) hace la regla obligatoria y simple: **lo que no lleva `type` se conserva tal cual; lo que lleva `type` se borra**.

```ts
import { Usuario } from './usuarios'
// Error: 'Usuario' is a type and must be imported using a type-only import
// when 'verbatimModuleSyntax' is enabled.
```

Es la opción recomendada para proyectos nuevos con bundlers. Esta app la tiene activada: abre cualquier archivo de `src/` y verás `import type`.

## Diferencia entre las dos formas

```ts
import type { A, B } from './x'    // todo el import se borra
import { type A, type B } from './x' // con verbatimModuleSyntax queda: import {} from './x'
```

La segunda conserva un `import './x'` vacío, que ejecuta los efectos secundarios del módulo. Normalmente quieres la primera si todo son tipos.

## Usar una clase como tipo

Si importas una clase solo para anotar, también puede ser `import type`:

```ts
import type { Punto } from './punto'
function f(p: Punto) {}       // ✓ como tipo
new Punto(1, 2)
// Error: 'Punto' cannot be used as a value because it was imported using 'import type'.
```

## isolatedModules

Opción relacionada, más antigua: avisa de cualquier construcción que no se pueda compilar archivo por archivo. `verbatimModuleSyntax` la incluye en la práctica.

## erasableSyntaxOnly

Opción reciente (TS 5.8): prohíbe la sintaxis de TS que **genera** código (`enum`, `namespace`, parameter properties). Así el código se puede ejecutar simplemente **borrando** los tipos, como hace Node 23+ con archivos `.ts`. Esta app también la activa.
