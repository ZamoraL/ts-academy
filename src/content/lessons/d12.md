## readonly

Una propiedad `readonly` no se puede reasignar tras crear el objeto:

```ts
interface Usuario {
  readonly id: number
  nombre: string
}

const u: Usuario = { id: 1, nombre: 'Ada' }
u.nombre = 'Grace' // ✓
u.id = 2
// Error: Cannot assign to 'id' because it is a read-only property.
```

`readonly` es **superficial**: el contenido de un objeto `readonly` sí se puede modificar.

```ts
interface Casa {
  readonly dueño: { nombre: string }
}
const c: Casa = { dueño: { nombre: 'Ana' } }
c.dueño.nombre = 'Luis' // ✓
c.dueño = { nombre: 'Luis' } // Error
```

Como `const`, comprueba en compilación; no congela nada en runtime (para eso existe `Object.freeze`).

## Index signatures

Cuando no conoces los nombres de las propiedades de antemano, pero sí el **tipo** de sus valores:

```ts
interface Diccionario {
  [palabra: string]: string
}

const traducciones: Diccionario = {
  hola: 'hello',
  adios: 'bye',
}
traducciones.gato = 'cat' // ✓
traducciones.numero = 1   // Error: Type 'number' is not assignable to type 'string'.
```

Las claves pueden ser `string`, `number`, `symbol` o template literal types.

### Mezclar con propiedades fijas

Las propiedades fijas deben cumplir la firma:

```ts
interface ConfigNumerica {
  [clave: string]: number
  version: number   // ✓
  nombre: string    // Error: Property 'nombre' of type 'string' is not assignable to 'string' index type 'number'.
}
```

Solución: ampliar la firma con una unión (`[clave: string]: number | string`).

### Leer de una index signature

TS asume que **la clave existe**:

```ts
const t = traducciones['perro'] // string… aunque no exista
```

La opción `noUncheckedIndexedAccess` cambia esto a `string | undefined`. Si no la tienes activada, comprueba tú.

## Record

Atajo para lo mismo, muy usado:

```ts
type Diccionario = Record<string, string>
type Notas = Record<'mate' | 'lengua', number> // claves exactas
```

Verás `Record` y otros utility types en el bloque E.
