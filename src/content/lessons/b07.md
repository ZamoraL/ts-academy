Los **módulos** dividen el código en archivos. Cada archivo decide qué **exporta** (hace público) y qué **importa** de otros.

## Exportaciones con nombre

```js
// matematicas.js
export const PI = 3.14159

export function sumar(a, b) {
  return a + b
}

function ayudante() {} // no exportada: privada del módulo
```

```js
// app.js
import { sumar, PI } from './matematicas.js'
sumar(1, 2)
```

Los nombres deben coincidir. Puedes renombrar:

```js
import { sumar as add } from './matematicas.js'
```

## Exportación por defecto

Un módulo puede tener **una** exportación por defecto:

```js
// Boton.jsx
export default function Boton() { ... }
```

```js
import Boton from './Boton.jsx'      // sin llaves, cualquier nombre
import MiBoton from './Boton.jsx'    // también vale
```

Muchos equipos prefieren exportaciones con nombre: el editor puede renombrarlas y autocompletarlas mejor.

## Importar todo

```js
import * as mates from './matematicas.js'
mates.sumar(1, 2)
```

## Paquetes

```js
import { useState } from 'react'  // sin ./ → viene de node_modules
```

## Cada módulo tiene su propio alcance

Las variables de un módulo no se filtran a los demás. Solo lo exportado es visible. Por eso los ejercicios de esta app son independientes entre sí.

## En los ejercicios

Aquí no hay varios archivos, así que no puedes usar `import`. Pero **sí puedes usar `export`**: los tests leen lo que exportes a través de un objeto `exports`.
