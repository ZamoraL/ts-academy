Ya sabes JavaScript. **TypeScript es JavaScript con tipos**: todo el JS que escribiste es TS válido, y TS añade una capa que describe qué forma tienen tus datos.

## El problema que resuelve

En JavaScript los errores de tipo aparecen **al ejecutar**, a veces en producción:

```js
function precioFinal(producto) {
  return producto.precio * producto.cantidad
}

precioFinal({ precio: 10, cantdad: 2 }) // NaN, sin ningún aviso
```

En TypeScript describes la forma esperada y el editor te avisa **mientras escribes**:

```ts
function precioFinal(producto: { precio: number; cantidad: number }) {
  return producto.precio * producto.cantidad
}

precioFinal({ precio: 10, cantdad: 2 })
// Error: Object literal may only specify known properties,
// but 'cantdad' does not exist... Did you mean to write 'cantidad'?
```

## Qué te da

- **Errores antes de ejecutar**: typos, `undefined` olvidados, argumentos en el orden incorrecto.
- **Autocompletado real**: el editor sabe qué propiedades tiene cada objeto.
- **Refactors seguros**: renombras una propiedad y TS te muestra cada sitio que hay que cambiar.
- **Documentación viva**: los tipos dicen qué espera y qué devuelve cada función.

## Qué NO hace

- **No cambia cómo se ejecuta tu código.** Los tipos se borran al compilar: el navegador recibe JavaScript normal.
- **No valida datos en tiempo de ejecución.** Si una API devuelve algo inesperado, TS no lo sabe (verás cómo resolverlo en el bloque H).
