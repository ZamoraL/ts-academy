## Parámetros

Anota cada parámetro después de su nombre:

```ts
function saludar(nombre: string, veces: number) {
  return `Hola ${nombre}! `.repeat(veces)
}

saludar('Ada', 2)   // ✓
saludar(2, 'Ada')   // Error: Argument of type 'number' is not assignable to parameter of type 'string'.
saludar('Ada')      // Error: Expected 2 arguments, but got 1.
```

TS también comprueba **cuántos** argumentos pasas.

## Tipo de retorno

Se escribe después de los paréntesis:

```ts
function area(ancho: number, alto: number): number {
  return ancho * alto
}
```

Normalmente TS **infiere** el retorno, así que es opcional. Anotarlo es útil para:

- documentar funciones públicas,
- que TS te avise si un `return` devuelve algo distinto de lo prometido.

```ts
function clasificar(n: number): string {
  if (n > 0) return 'positivo'
  if (n < 0) return 'negativo'
  // Error: Function lacks ending return statement and return type does not include 'undefined'.
}
```

## Funciones que devuelven promesas

```ts
async function cargarNombre(): Promise<string> {
  const r = await fetch('/api/nombre')
  return r.text()
}
```

Una función `async` siempre devuelve `Promise<T>`.

## Funciones flecha

```ts
const doble = (n: number): number => n * 2
```

## Funciones anónimas: tipado contextual

Cuando pasas una función como argumento, TS **ya sabe** el tipo de sus parámetros por el contexto:

```ts
const nombres = ['Ana', 'Luis']
nombres.forEach((n) => {
  console.log(n.toUpperCase()) // n: string, sin anotar
})
```

Por eso en `map`, `filter`, etc. casi nunca anotarás nada.

## Parámetros por defecto

El defecto también sirve para inferir el tipo:

```ts
function saludar(nombre = 'Invitado') { } // nombre: string
```
