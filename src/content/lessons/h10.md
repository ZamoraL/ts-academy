Juntemos `useEffect`, `fetch`, genéricos y uniones discriminadas en un patrón reutilizable.

## El estado de una petición

```tsx
type EstadoPeticion<T> =
  | { estado: 'cargando' }
  | { estado: 'error'; error: string }
  | { estado: 'ok'; datos: T }
```

## Un hook genérico

```tsx
function useFetch<T>(url: string): EstadoPeticion<T> {
  const [resultado, setResultado] = useState<EstadoPeticion<T>>({ estado: 'cargando' })

  useEffect(() => {
    let cancelado = false
    setResultado({ estado: 'cargando' })

    async function cargar() {
      try {
        const r = await fetch(url)
        if (!r.ok) throw new Error(`HTTP ${r.status}`)
        const datos = (await r.json()) as T
        if (!cancelado) setResultado({ estado: 'ok', datos })
      } catch (e) {
        if (!cancelado) setResultado({ estado: 'error', error: e instanceof Error ? e.message : String(e) })
      }
    }

    void cargar()
    return () => {
      cancelado = true
    }
  }, [url])

  return resultado
}
```

- La función del efecto no puede ser `async` (debe devolver la limpieza, no una promesa): por eso se define `cargar` dentro.
- `void cargar()` indica explícitamente que no esperamos la promesa.

## Usarlo

```tsx
interface Post { id: number; title: string }

function Posts() {
  const r = useFetch<Post[]>('https://jsonplaceholder.typicode.com/posts')

  if (r.estado === 'cargando') return <p>Cargando…</p>
  if (r.estado === 'error') return <p role="alert">{r.error}</p>
  return (
    <ul>
      {r.datos.map((p) => <li key={p.id}>{p.title}</li>)}
    </ul>
  )
}
```

TS estrecha `r` en cada rama: `r.datos` solo existe cuando `estado === 'ok'`.

## El problema del `as T`

`r.json()` devuelve `Promise<any>`. El `as T` es una **promesa tuya**: si la API cambia o devuelve otra cosa, TS no lo sabrá y el error aparecerá lejos, en el render. La siguiente unidad lo resuelve validando con Zod.

## Capa de API

En apps reales, separa las llamadas en funciones tipadas, fuera de los componentes:

```ts
// api.ts
export async function obtenerPosts(): Promise<Post[]> { ... }
export async function crearPost(datos: Omit<Post, 'id'>): Promise<Post> { ... }
```

Así los componentes no conocen URLs ni detalles de `fetch`, y es fácil reemplazarlas en tests.

## En producción

Para datos remotos en apps grandes se usan librerías como **TanStack Query** (caché, reintentos, invalidación, estados de carga). Por dentro hacen lo mismo que este hook, mucho más completo. Con lo que sabes, entenderás su API tipada sin problema.
