## Pick\<T, K>

Un tipo con **solo** algunas propiedades:

```ts
interface Usuario {
  id: number
  nombre: string
  email: string
  password: string
  creado: Date
}

type Tarjeta = Pick<Usuario, 'id' | 'nombre'>
// { id: number; nombre: string }
```

## Omit\<T, K>

Un tipo **sin** algunas propiedades:

```ts
type UsuarioPublico = Omit<Usuario, 'password'>
type NuevoUsuario = Omit<Usuario, 'id' | 'creado'> // lo que envía un formulario
```

`Pick` restringe `K` a claves existentes (`keyof T`); `Omit` acepta cualquier string, así que un typo en `Omit` **no** da error. Revisa bien.

### ¿Pick u Omit?

Elige el que nombre menos claves y exprese mejor la intención. "Un usuario sin la contraseña" es `Omit`; "la vista previa de un post" es `Pick`.

## Record\<K, V>

Un objeto con claves de tipo `K` y valores de tipo `V`:

```ts
type Rol = 'admin' | 'editor' | 'lector'

const permisos: Record<Rol, string[]> = {
  admin: ['*'],
  editor: ['leer', 'escribir'],
  lector: ['leer'],
}
```

Con una unión de literales, TS exige **todas** las claves. Si falta una, error. Perfecto para tablas de configuración exhaustivas.

```ts
const etiquetas: Record<Rol, string> = { admin: 'Admin', editor: 'Editor' }
// Error: Property 'lector' is missing...
```

Con `string`, es un diccionario abierto:

```ts
const cache: Record<string, number> = {}
```

## Exclude y Extract

Sobre **uniones** (no objetos):

```ts
type Estado = 'activo' | 'inactivo' | 'baneado'
type Visible = Exclude<Estado, 'baneado'> // 'activo' | 'inactivo'

type Evento = { tipo: 'click'; x: number } | { tipo: 'tecla'; codigo: string }
type Click = Extract<Evento, { tipo: 'click' }> // { tipo: 'click'; x: number }
```

## NonNullable

```ts
type A = NonNullable<string | null | undefined> // string
```

## Componer

```ts
type EditarUsuario = Partial<Pick<Usuario, 'nombre' | 'email'>>
type Ficha = Readonly<Omit<Usuario, 'password'>>
```
