`async` / `await` es una forma de escribir código con promesas que **se lee como código síncrono**.

## async

Una función `async` **siempre devuelve una promesa**:

```js
async function obtenerNumero() {
  return 42
}
obtenerNumero() // Promise { 42 }
obtenerNumero().then((n) => console.log(n)) // 42
```

## await

Dentro de una función `async`, `await` **pausa esa función** hasta que la promesa se resuelva, y devuelve su valor:

```js
async function mostrarUsuario() {
  const respuesta = await fetch('/api/usuario')
  const usuario = await respuesta.json()
  console.log(usuario.nombre)
}
```

Equivale a la cadena de `.then`, pero sin anidar. Mientras la función está pausada, el resto del programa sigue funcionando (event loop).

## Errores: try / catch

Si la promesa se rechaza, `await` **lanza** el error:

```js
async function cargar() {
  try {
    const r = await fetch('/api/datos')
    return await r.json()
  } catch (error) {
    console.log('Falló:', error.message)
    return null
  }
}
```

## Secuencial vs paralelo

```js
// ❌ secuencial: espera a A antes de empezar B
const a = await cargarA()
const b = await cargarB()

// ✅ paralelo: empiezan las dos a la vez
const [a, b] = await Promise.all([cargarA(), cargarB()])
```

Usa la forma secuencial solo cuando B **necesita** el resultado de A.

## Funciones flecha async

```js
const cargar = async (id) => {
  const r = await fetch(`/api/items/${id}`)
  return r.json()
}
```

## Error común: olvidar await

```js
async function f() {
  const datos = cargarDatos() // ¡falta await!
  console.log(datos.nombre)   // undefined: datos es una Promise
}
```

TypeScript detecta este error: verá que `datos` es `Promise<...>`, que no tiene `nombre`.
