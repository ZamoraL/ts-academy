Algunas funciones aceptan argumentos de distintas formas, y **su retorno depende** de cuál uses. Las *sobrecargas* (overloads) describen cada combinación.

## Sintaxis

Escribes varias **firmas** (sin cuerpo) y luego **una** implementación:

```ts
function crearFecha(timestamp: number): Date
function crearFecha(dia: number, mes: number, anio: number): Date
function crearFecha(diaOTimestamp: number, mes?: number, anio?: number): Date {
  if (mes !== undefined && anio !== undefined) {
    return new Date(anio, mes - 1, diaOTimestamp)
  }
  return new Date(diaOTimestamp)
}

crearFecha(1_700_000_000_000) // ✓
crearFecha(15, 3, 2026)       // ✓
crearFecha(15, 3)
// Error: No overload expects 2 arguments, but overloads do exist that expect either 1 or 3 arguments.
```

- Las firmas de sobrecarga son lo que ve quien llama a la función.
- La firma de implementación **no es visible** desde fuera; tiene que ser compatible con todas las sobrecargas.

## Retorno que depende del argumento

```ts
function invertir(x: string): string
function invertir(x: number[]): number[]
function invertir(x: string | number[]): string | number[] {
  if (typeof x === 'string') return [...x].reverse().join('')
  return [...x].reverse()
}

const a = invertir('hola')  // string
const b = invertir([1, 2])  // number[]
```

Sin sobrecargas, ambos serían `string | number[]` y tendrías que estrecharlos al usarlos.

## Prefiere uniones cuando puedas

El Handbook es claro: **si una unión basta, úsala**. Las sobrecargas tienen límites:

```ts
function longitud(s: string): number
function longitud(arr: any[]): number
function longitud(x: any) { return x.length }

longitud(Math.random() > 0.5 ? 'hola' : [0])
// Error: No overload matches this call.
```

TS elige **una** sobrecarga por llamada, y ninguna acepta `string | number[]`. Con una unión no pasa:

```ts
function longitud(x: string | any[]): number {
  return x.length
}
```

**Regla:** usa sobrecargas solo cuando el **tipo de retorno** depende de los argumentos. Si el retorno es siempre el mismo, usa uniones u opcionales.

> En el bloque E verás otra herramienta para esto: genéricos y conditional types.
