Las funciones son valores, así que también tienen tipo.

## Function type expressions

```ts
type Operacion = (a: number, b: number) => number

const sumar: Operacion = (a, b) => a + b     // a y b ya son number
const restar: Operacion = (a, b) => a - b
```

Los nombres de los parámetros (`a`, `b`) son obligatorios en la sintaxis, pero no tienen que coincidir con los de la implementación.

### Como parámetro

```ts
function saludar(fn: (mensaje: string) => void) {
  fn('Hola, mundo')
}

saludar((m) => console.log(m))
```

### Como retorno

```ts
function multiplicador(factor: number): (n: number) => number {
  return (n) => n * factor
}
```

## Callbacks y void

Un callback de tipo `() => void` **puede** devolver algo; simplemente se ignora:

```ts
const nums: number[] = []
;[1, 2, 3].forEach((n) => nums.push(n)) // push devuelve number, forEach espera void: OK
```

## Call signatures

Una función en JS puede tener propiedades. Para describirla, usa un tipo de objeto con una **firma de llamada**:

```ts
type FuncionDescrita = {
  descripcion: string
  (valor: number): boolean
}

function ejecutar(fn: FuncionDescrita) {
  console.log(fn.descripcion + ' devolvió ' + fn(6))
}

function esPar(n: number) {
  return n % 2 === 0
}
esPar.descripcion = 'esPar'
ejecutar(esPar) // ✓
```

Nota la diferencia de sintaxis: en un tipo de objeto se usa `:` (`(valor: number): boolean`), no `=>`.

## Construct signatures

Para cosas que se llaman con `new`:

```ts
type ConstructorPunto = {
  new (x: number, y: number): { x: number; y: number }
}
```

Lo verás poco; aparece al escribir funciones que reciben clases.

## Métodos en interfaces

Dos formas de declarar un método:

```ts
interface Calculadora {
  sumar(a: number, b: number): number        // sintaxis de método
  restar: (a: number, b: number) => number   // propiedad con tipo función
}
```

Ambas funcionan igual para el uso diario.
