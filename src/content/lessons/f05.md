Tres opciones que confunden a todo el mundo al principio.

## target

Qué versión de JavaScript **genera** `tsc`. Si usas sintaxis más moderna que el target, TS la transforma ("downlevel"):

```ts
// con target: "es5", esto...
const f = (a = 1) => a ?? 2
// ...se convierte en funciones clásicas, var y comprobaciones manuales
```

Hoy todos los navegadores modernos soportan ES2022+. Valores típicos: `"es2022"` o `"esnext"`.

`target` **no** añade polyfills: si usas `Array.prototype.toSorted` con `target: "es5"`, TS no lo implementa por ti.

## lib

Qué **APIs** existen en el entorno (sus tipos). Por defecto depende de `target`.

```json
{ "lib": ["ES2022", "DOM", "DOM.Iterable"] }
```

- `"ES2023"` añade los tipos de `toSorted`, `findLast`…
- `"DOM"` añade `document`, `window`, `fetch`, `HTMLElement`…
- Para Node, no incluyas `DOM`: instala `@types/node`.

Si TS dice *"Property 'toSorted' does not exist on type 'number[]'"*, tu `lib` (o `target`) es demasiado antiguo.

## module

Qué sistema de módulos usa la **salida**:

| Valor | Para |
|---|---|
| `"esnext"` / `"es2022"` | Bundlers (Vite, webpack) |
| `"nodenext"` | Node.js moderno (respeta `"type": "module"` del package.json) |
| `"commonjs"` | Node antiguo (`require`/`module.exports`) |
| `"preserve"` | Deja los imports tal cual (para bundlers, TS 5.4+) |

## moduleResolution

Cómo **encuentra** TS los archivos que importas:

| Valor | Comportamiento |
|---|---|
| `"bundler"` | Como Vite/webpack: sin extensiones, lee `exports` del package.json |
| `"nodenext"` | Como Node ESM: extensiones obligatorias (`./x.js`) |

## Configuraciones típicas

### App con Vite + React

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "noEmit": true,
    "strict": true
  }
}
```

`noEmit`: TS solo comprueba; Vite genera el JS.

### Librería o servidor en Node

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "outDir": "dist",
    "declaration": true,
    "strict": true
  }
}
```

## jsx

Para React: `"react-jsx"` (el runtime moderno, sin `import React` en cada archivo).
