TS no mira cada `if` por separado: analiza **todos los caminos** que puede seguir tu código. A eso se le llama *control flow analysis*.

## Código inalcanzable y return

```ts
function padLeft(padding: number | string, input: string) {
  if (typeof padding === 'number') {
    return ' '.repeat(padding) + input
  }
  return padding + input // TS sabe que aquí padding solo puede ser string
}
```

TS ve que la rama `number` termina con `return`, así que el resto de la función solo se alcanza con `string`. Lo mismo con `throw`, `break` y `continue`.

## Asignaciones

Cada asignación cambia el tipo "actual" de una variable, dentro de su tipo **declarado**:

```ts
let x = Math.random() < 0.5 ? 10 : 'hola' // declarado: string | number
x // string | number

x = 1
x // number

x = 'adiós'
x // string

x = true
// Error: Type 'boolean' is not assignable to type 'string | number'.
```

## Dentro de callbacks

Aquí hay una sutileza importante. TS **olvida** el narrowing de propiedades dentro de funciones que se crean después:

```ts
function nombresMasLargos(usuario: { nombre?: string }, lista: string[]) {
  if (usuario.nombre) {
    return lista.filter((x) => x.length > usuario.nombre.length)
    // Error: 'usuario.nombre' is possibly 'undefined'.
  }
  return []
}
```

¿Por qué? El callback podría ejecutarse más tarde, cuando alguien ya haya cambiado `usuario.nombre`. La solución es copiar el valor a una **constante**, que no puede cambiar:

```ts
function nombresMasLargos(usuario: { nombre?: string }, lista: string[]) {
  const nombre = usuario.nombre
  if (nombre) {
    return lista.filter((x) => x.length > nombre.length) // ✓
  }
  return []
}
```

Este patrón (sacar a una `const` y luego comprobar) lo usarás muchísimo.

## Ver el flujo

La mejor manera de aprender esto es experimentar: escribe una variable de tipo unión, añade comprobaciones y pasa el ratón por encima en distintos puntos del código.
