Los componentes deben ser **puros**: calcular el JSX a partir de props y estado, sin efectos secundarios. Pero a veces necesitas sincronizarte con algo **externo** a React: la red, un timer, el título de la página, `localStorage`. Para eso está **`useEffect`**.

```jsx
import { useEffect, useState } from 'react'

function Titulo({ pendientes }) {
  useEffect(() => {
    document.title = `(${pendientes}) Mis tareas`
  }, [pendientes])

  return <h1>Mis tareas</h1>
}
```

El efecto se ejecuta **después** de que React actualiza el DOM.

## El array de dependencias

| Dependencias | Se ejecuta |
|---|---|
| `useEffect(fn)` | Después de **cada** render |
| `useEffect(fn, [])` | Solo después del **primer** render (al montar) |
| `useEffect(fn, [a, b])` | Al montar y cuando cambie `a` o `b` |

Incluye **todos** los valores de props/estado que usa el efecto. Si te falta alguno, el efecto trabajará con datos viejos.

## Limpieza

Si el efecto crea algo que hay que deshacer (un timer, una suscripción), devuelve una función de limpieza:

```jsx
function Reloj() {
  const [ahora, setAhora] = useState(new Date())

  useEffect(() => {
    const id = setInterval(() => setAhora(new Date()), 1000)
    return () => clearInterval(id) // al desmontar o antes de re-ejecutar
  }, [])

  return <p>{ahora.toLocaleTimeString()}</p>
}
```

## Cargar datos

```jsx
function Perfil({ id }) {
  const [usuario, setUsuario] = useState(null)

  useEffect(() => {
    let cancelado = false
    fetch(`/api/usuarios/${id}`)
      .then((r) => r.json())
      .then((datos) => {
        if (!cancelado) setUsuario(datos)
      })
    return () => {
      cancelado = true // si id cambia antes de que llegue la respuesta, ignórala
    }
  }, [id])

  if (!usuario) return <p>Cargando…</p>
  return <h2>{usuario.nombre}</h2>
}
```

En apps reales se suele usar una librería (TanStack Query, SWR) o el framework (Next.js) para esto, pero entender el patrón es fundamental.

## Cuándo NO usar useEffect

Muchos efectos son innecesarios. El más común:

```jsx
// ❌ estado derivado con efecto
const [filtradas, setFiltradas] = useState([])
useEffect(() => {
  setFiltradas(tareas.filter((t) => !t.hecha))
}, [tareas])

// ✅ calcúlalo directamente
const filtradas = tareas.filter((t) => !t.hecha)
```

Y la lógica que responde a una acción del usuario va en el **handler**, no en un efecto. La documentación de React tiene una página entera sobre esto: [You Might Not Need an Effect](https://es.react.dev/learn/you-might-not-need-an-effect).

## Persistir en localStorage

```jsx
const [tareas, setTareas] = useState(() => JSON.parse(localStorage.getItem('tareas') ?? '[]'))

useEffect(() => {
  localStorage.setItem('tareas', JSON.stringify(tareas))
}, [tareas])
```

Pasar una **función** a `useState` hace que solo se lea `localStorage` en el primer render.
