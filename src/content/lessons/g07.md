Para responder a interacciones, pasa una **función** a props como `onClick`, `onChange`, `onSubmit`...

```jsx
function Boton() {
  function manejarClic() {
    alert('¡Clic!')
  }
  return <button onClick={manejarClic}>Púlsame</button>
}
```

## Pasa la función, no la llames

```jsx
<button onClick={manejarClic}>     ✅ se llama al hacer clic
<button onClick={manejarClic()}>   ❌ se llama al renderizar
<button onClick={() => manejarClic(5)}> ✅ con argumentos, envuelve en una flecha
```

## El objeto evento

El handler recibe un evento con información:

```jsx
<input onChange={(e) => console.log(e.target.value)} />
<a href="/x" onClick={(e) => { e.preventDefault(); navegar() }}>Ir</a>
```

- `e.target`: el elemento que disparó el evento.
- `e.preventDefault()`: evita el comportamiento por defecto (enviar un formulario, seguir un link).
- `e.stopPropagation()`: evita que el evento suba a los padres.

## Handlers como props

Un componente puede recibir el handler del padre. Por convención, las props se llaman `onAlgo` y las funciones `manejarAlgo` (en inglés, `onX` / `handleX`):

```jsx
function Boton({ onClick, children }) {
  return <button onClick={onClick}>{children}</button>
}

function Barra() {
  return (
    <>
      <Boton onClick={() => alert('Reproduciendo')}>Play</Boton>
      <Boton onClick={() => alert('Pausado')}>Pausa</Boton>
    </>
  )
}
```

Así el botón no sabe **qué** hace: solo avisa al padre. Es la base para que los componentes se comuniquen hacia arriba.

## Eventos comunes

| Prop | Cuándo |
|---|---|
| `onClick` | Clic |
| `onChange` | Cambia el valor de un input |
| `onSubmit` | Se envía un formulario |
| `onKeyDown` | Se pulsa una tecla |
| `onFocus` / `onBlur` | Entra / sale el foco |
| `onMouseEnter` / `onMouseLeave` | Pasa el ratón |

## Los handlers pueden tener efectos

A diferencia del cuerpo del componente (que debe ser "puro"), los handlers son el lugar para **hacer cosas**: cambiar estado, llamar a una API, navegar.
