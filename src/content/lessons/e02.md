## Tipos genéricos

No solo las funciones: los **tipos** también pueden tener parámetros.

```ts
type Caja<T> = {
  valor: T
}

const a: Caja<number> = { valor: 1 }
const b: Caja<string> = { valor: 'x' }
```

```ts
interface Respuesta<T> {
  ok: boolean
  datos: T
  error?: string
}

type RespuestaUsuarios = Respuesta<Usuario[]>
```

Esto es exactamente lo que harás para tipar respuestas de APIs.

## Uniones genéricas

```ts
type Resultado<T> =
  | { ok: true; valor: T }
  | { ok: false; error: string }

function dividir(a: number, b: number): Resultado<number> {
  if (b === 0) return { ok: false, error: 'División entre 0' }
  return { ok: true, valor: a / b }
}

const r = dividir(1, 2)
if (r.ok) r.valor // number
else r.error      // string
```

Un patrón muy común para manejar errores **sin excepciones**.

## Tipos de función genéricos

```ts
type Transformador<T, U> = (entrada: T) => U

const aTexto: Transformador<number, string> = (n) => n.toFixed(2)
```

Fíjate en la diferencia de dónde va `<T>`:

```ts
type A<T> = (x: T) => T   // el tipo es genérico: A<number> es (x: number) => number
type B = <T>(x: T) => T   // la función es genérica: cada llamada elige T
```

`B` describe una función como `identidad`. `A<number>` es una función concreta de números.

## Funciones que trabajan con tipos genéricos

```ts
function envolver<T>(valor: T): Caja<T> {
  return { valor }
}

function mapCaja<T, U>(caja: Caja<T>, fn: (v: T) => U): Caja<U> {
  return { valor: fn(caja.valor) }
}

mapCaja(envolver(3), (n) => n > 2) // Caja<boolean>
```

## Genéricos que usan otros genéricos

```ts
type Lista<T> = T[]
type Diccionario<T> = { [clave: string]: T }
type Paginado<T> = Respuesta<{ items: T[]; total: number }>
```

Así se construyen tipos complejos a partir de piezas pequeñas.
