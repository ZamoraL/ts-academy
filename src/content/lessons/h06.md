`useRef` guarda un valor que **persiste entre renders** pero **no provoca un nuevo render** al cambiar. Dos usos principales.

## 1. Referencias al DOM

```tsx
import { useRef } from 'react'

function Buscador() {
  const inputRef = useRef<HTMLInputElement>(null)

  function enfocar() {
    inputRef.current?.focus()
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={enfocar}>Buscar</button>
    </>
  )
}
```

- El genérico es el **tipo de elemento**: `HTMLInputElement`, `HTMLDivElement`, `HTMLCanvasElement`...
- El inicial es `null`: el elemento todavía no existe en el primer render.
- Por eso `current` es `HTMLInputElement | null` y necesitas `?.` o una comprobación.

## 2. Valores mutables que no son estado

Un id de timer, el valor anterior de algo, un contador interno:

```tsx
function Cronometro() {
  const [segundos, setSegundos] = useState(0)
  const intervalo = useRef<number | null>(null)

  function iniciar() {
    if (intervalo.current !== null) return
    intervalo.current = window.setInterval(() => setSegundos((s) => s + 1), 1000)
  }

  function parar() {
    if (intervalo.current !== null) clearInterval(intervalo.current)
    intervalo.current = null
  }

  return (...)
}
```

Cambiar `intervalo.current` no re-renderiza: perfecto para datos que la interfaz no muestra.

`window.setInterval` devuelve `number`. Sin `window.`, en proyectos con tipos de Node, TS podría tomar la versión de Node (`NodeJS.Timeout`). Alternativa portable: `ReturnType<typeof setInterval>`.

## ¿Ref o estado?

| | `useState` | `useRef` |
|---|---|---|
| Cambiarlo re-renderiza | Sí | No |
| Se muestra en la interfaz | Sí | No debería |
| Leer durante el render | Sí | Evítalo |

Regla: si se ve en pantalla, es estado. Si no, puede ser ref.

## No leas refs durante el render

```tsx
function Mal() {
  const ref = useRef(0)
  ref.current++              // ❌ durante el render
  return <p>{ref.current}</p> // ❌ no se actualizará cuando debería
}
```

Lee y escribe refs en handlers y efectos.

## Pasar refs a tus componentes

En React 19, `ref` es una prop normal para componentes de función:

```tsx
function CampoTexto({ ref, ...props }: ComponentProps<'input'>) {
  return <input ref={ref} {...props} />
}
```

(En versiones anteriores hacía falta `forwardRef`, que verás en mucho código existente.)
