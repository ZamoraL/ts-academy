Un **enum** es una de las pocas características de TypeScript que **genera código** en runtime.

## Enums numéricos

```ts
enum Direccion {
  Arriba,    // 0
  Abajo,     // 1
  Izquierda, // 2
  Derecha,   // 3
}

function mover(d: Direccion) {}
mover(Direccion.Arriba)
```

Los valores se numeran automáticamente desde 0 (o desde el que pongas al primero).

## Enums de strings

```ts
enum Estado {
  Activo = 'ACTIVO',
  Inactivo = 'INACTIVO',
}
```

Más fáciles de depurar: en un log ves `'ACTIVO'` en vez de `0`.

## Qué genera

```ts
enum Color { Rojo = 'ROJO', Verde = 'VERDE' }
```

```js
var Color;
(function (Color) {
  Color["Rojo"] = "ROJO";
  Color["Verde"] = "VERDE";
})(Color || (Color = {}));
```

Un objeto real en runtime. Los numéricos además generan un mapeo inverso (`Direccion[0] === 'Arriba'`).

## Problemas de los enums

- **No son "solo tipos"**: no funcionan con herramientas que simplemente borran tipos (Node con `.ts`, `erasableSyntaxOnly`).
- Los numéricos aceptan cualquier número: `mover(42)` compila.
- Un enum de strings **no** acepta el string literal: `f('ACTIVO')` es error, hay que escribir `Estado.Activo`. Incómodo con datos de APIs.
- `const enum` tiene más problemas aún con herramientas que compilan archivo por archivo.

## La alternativa moderna: objeto as const + unión

```ts
const Estado = {
  Activo: 'ACTIVO',
  Inactivo: 'INACTIVO',
} as const

type Estado = (typeof Estado)[keyof typeof Estado] // 'ACTIVO' | 'INACTIVO'

function cambiar(e: Estado) {}
cambiar(Estado.Activo) // ✓
cambiar('ACTIVO')      // ✓ también, ideal para datos externos
cambiar('BORRADO')     // Error
```

- Mismo uso (`Estado.Activo`) y autocompletado.
- Es JavaScript normal.
- Puedes iterar los valores: `Object.values(Estado)`.

Sí, se puede tener un valor y un tipo con el **mismo nombre**: viven en "espacios" distintos.

## O simplemente una unión

Si no necesitas el objeto en runtime:

```ts
type Estado = 'ACTIVO' | 'INACTIVO'
```

Es lo más común en código TS moderno.

## ¿Entonces nunca enums?

Los verás en muchos proyectos y librerías existentes, así que debes saber leerlos. En código nuevo, el Handbook y la mayoría de equipos prefieren uniones de literales u objetos `as const`.
