Con los tipos y las funciones listos, toca la interfaz. Empieza por componentes **pequeños y presentacionales**: reciben datos por props, no tienen estado propio y no saben de dónde vienen los datos.

## De abajo hacia arriba

```
ListaGastos
└─ FilaGasto
   ├─ EtiquetaCategoria
   └─ Monto
```

### Monto

```tsx
export function Monto({ valor }: { valor: number }) {
  return <span className={valor < 0 ? 'negativo' : undefined}>{formatearMonto(valor)}</span>
}
```

Encapsular el formato en un componente garantiza que todos los montos de la app se vean igual.

### EtiquetaCategoria

Un `Record<Categoria, string>` para los iconos: si alguien añade una categoría, TS exige añadir su icono.

```tsx
const ICONOS: Record<Categoria, string> = {
  comida: '🍔',
  transporte: '🚌',
  ...
}
```

### FilaGasto

Recibe el gasto y un callback. Usa elementos semánticos y etiquetas accesibles:

```tsx
<li>
  <span>{gasto.descripcion}</span>
  <EtiquetaCategoria categoria={gasto.categoria} />
  <Monto valor={gasto.monto} />
  <button aria-label={`Borrar ${gasto.descripcion}`} onClick={() => onBorrar(gasto.id)}>✕</button>
</li>
```

Un botón con solo un icono **necesita** `aria-label`: sin él, un lector de pantalla diría "botón ✕".

### ListaGastos

Ordena (más recientes primero) sin mutar las props y maneja el caso vacío.

## Props: tipos derivados

En vez de repetir tipos, reutiliza los del dominio:

```tsx
interface FilaGastoProps {
  gasto: Gasto
  onBorrar: (id: Gasto['id']) => void
}
```

`Gasto['id']`: si el id cambia de `string` a `number`, esta prop se actualiza sola.

## Por qué presentacionales

- Se prueban fácil: render con props y comprobar.
- Se reutilizan: `ListaGastos` sirve igual con datos locales o remotos.
- El estado vive en un solo sitio (lo verás en la unidad 4).
