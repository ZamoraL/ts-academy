`extends` crea una clase **a partir de otra**, heredando sus propiedades y métodos.

## Ejemplo

```js
class Animal {
  constructor(nombre) {
    this.nombre = nombre
  }
  describir() {
    return `${this.nombre} es un animal`
  }
  hablar() {
    return '...'
  }
}

class Perro extends Animal {
  constructor(nombre, raza) {
    super(nombre) // llama al constructor de Animal
    this.raza = raza
  }
  hablar() {
    return 'Guau' // sobrescribe el método del padre
  }
}

const p = new Perro('Rex', 'labrador')
p.describir() // 'Rex es un animal'  (heredado)
p.hablar()    // 'Guau'              (propio)
p instanceof Perro  // true
p instanceof Animal // true
```

## super

- En el constructor, `super(...)` **debe llamarse antes de usar `this`**.
- En un método, `super.metodo()` llama a la versión del padre:

```js
class Gato extends Animal {
  describir() {
    return super.describir() + ' y es un gato'
  }
}
```

## Errores personalizados

Un uso muy práctico de la herencia:

```js
class ErrorValidacion extends Error {
  constructor(campo, mensaje) {
    super(mensaje)
    this.name = 'ErrorValidacion'
    this.campo = campo
  }
}

try {
  throw new ErrorValidacion('email', 'Email inválido')
} catch (e) {
  if (e instanceof ErrorValidacion) console.log(e.campo) // 'email'
}
```

## ¿Herencia o composición?

La herencia profunda (A extiende B extiende C...) se vuelve rígida. En código moderno, y sobre todo en React, se prefiere **componer**: objetos y funciones pequeñas que se combinan. Usa `extends` para jerarquías simples y claras, como errores.
