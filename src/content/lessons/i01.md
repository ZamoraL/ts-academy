Llegaste al final. Durante 8 unidades vas a construir, pieza a pieza, un **gestor de gastos personales** con React y TypeScript: tipos del dominio, utilidades puras, componentes, reducer, datos remotos validados, formularios con validación, tests y una app integrada.

Cada unidad es un ejercicio independiente, pero todas comparten el mismo dominio. Al terminar, la unidad 8 te explica cómo llevarlo a un proyecto real en tu computadora y publicarlo.

## Paso 1: modelar el dominio

Antes de escribir componentes, define **qué datos existen**. Es la decisión más importante: con buenos tipos, el resto casi se escribe solo (y TS te avisa de cada inconsistencia).

### Las categorías

Una lista fija que necesitas en runtime (para un `<select>`) **y** como tipo:

```ts
export const CATEGORIAS = ['comida', 'transporte', 'ocio', 'hogar', 'otros'] as const
export type Categoria = (typeof CATEGORIAS)[number]
```

Una sola fuente de verdad (bloque E).

### El gasto

```ts
export interface Gasto {
  readonly id: string
  descripcion: string
  monto: number
  categoria: Categoria
  fecha: string // 'YYYY-MM-DD'
}
```

- `id` readonly: no debería cambiar nunca.
- La fecha como string ISO: se ordena y compara como texto, se serializa a JSON sin problemas.

### Tipos derivados

En lugar de redefinir, deriva con utility types:

```ts
export type NuevoGasto = Omit<Gasto, 'id'>        // lo que envía el formulario
export type CambiosGasto = Partial<NuevoGasto>     // para editar
export type ResumenPorCategoria = Record<Categoria, number>
```

Si mañana añades un campo a `Gasto`, todos se actualizan.

### Filtros

```ts
export interface Filtros {
  categoria: Categoria | 'todas'
  mes: string | null // 'YYYY-MM' o null para todos
}
```

## Tu ejercicio

Escribe estos tipos. Los tests de tipos comprobarán cada uno, por ejemplo que `NuevoGasto` no tenga `id`, que `ResumenPorCategoria` exija las cinco categorías y que `Categoria` se derive de `CATEGORIAS`.
