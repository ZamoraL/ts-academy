TypeScript incluye **utility types**: tipos genéricos predefinidos para transformaciones comunes. Ya sabes cómo están construidos (mapped types); ahora a usarlos.

## Partial\<T>

Todas las propiedades opcionales.

```ts
interface Tarea {
  titulo: string
  descripcion: string
  hecha: boolean
}

function actualizar(tarea: Tarea, cambios: Partial<Tarea>): Tarea {
  return { ...tarea, ...cambios }
}

actualizar(t, { hecha: true }) // ✓ no hace falta pasar todo
```

Ideal para funciones de actualización, formularios parciales y opciones.

## Required\<T>

Todas obligatorias (quita los `?`).

```ts
interface Opciones {
  ancho?: number
  alto?: number
}

const DEFECTOS: Required<Opciones> = { ancho: 800, alto: 600 }

function resolver(o: Opciones): Required<Opciones> {
  return { ...DEFECTOS, ...o }
}
```

Cuidado: si el usuario pasa `{ ancho: undefined }` explícitamente, el spread sobrescribe el defecto con `undefined`. La opción `exactOptionalPropertyTypes` de tsconfig distingue "ausente" de "undefined".

## Readonly\<T>

Todas `readonly`.

```ts
function congelar<T extends object>(obj: T): Readonly<T> {
  return Object.freeze(obj)
}

const c = congelar({ x: 1 })
c.x = 2 // Error: Cannot assign to 'x' because it is a read-only property.
```

Muy usado para estado inmutable (por ejemplo en reducers).

## Son superficiales

Como `readonly`, `Partial` y `Readonly` solo afectan **al primer nivel**:

```ts
type P = Partial<{ a: { b: string } }>
// { a?: { b: string } }   ← b sigue siendo obligatoria
```

Para versiones "profundas", tendrías que escribir un tipo recursivo:

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K]
}
```

## Combinarlos

```ts
type Borrador = Readonly<Partial<Tarea>>
```
