Un **archivo de declaración** (`.d.ts`) contiene **solo tipos**, sin implementación. Describe código JavaScript que existe en otro sitio.

## Por qué existen

Muchas librerías están escritas en JS. Para usarlas en TS con tipos, alguien escribe un `.d.ts` que describe su API:

```ts
// formatear.d.ts
export declare function formatearMoneda(n: number, moneda?: string): string
export declare const VERSION: string
```

La palabra `declare` dice "esto existe en runtime, confía en mí; aquí solo está el tipo".

## declare

```ts
declare const API_URL: string
declare function track(evento: string, datos?: object): void
declare class Mapa {
  constructor(contenedor: HTMLElement)
  centrar(lat: number, lng: number): void
}
declare namespace Analytics {
  function page(nombre: string): void
}
```

Útil también en tu propio código para variables globales que inyecta otra herramienta (por ejemplo un script en el HTML o una variable que reemplaza el bundler).

## Ampliar tipos globales

Si una librería añade algo a `window`:

```ts
declare global {
  interface Window {
    miApp: { version: string }
  }
}

window.miApp.version // ✓
```

Funciona gracias a la **fusión de interfaces** (declaration merging) que viste con `interface`.

Vite usa esto para tipar `import.meta.env`:

```ts
// vite-env.d.ts
interface ImportMetaEnv {
  readonly VITE_API_URL: string
}
```

## Generarlos

Si escribes una librería en TS, `tsc` puede generar los `.d.ts` automáticamente:

```json
{ "compilerOptions": { "declaration": true } }
```

Así quien use tu librería desde TS tiene los tipos.

## Módulos sin tipos

Si importas algo que TS no conoce (un `.svg`, una librería sin tipos):

```ts
// globals.d.ts
declare module '*.svg' {
  const url: string
  export default url
}

declare module 'libreria-vieja' // todo lo que importes será any
```
