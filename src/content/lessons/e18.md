Un **emisor de eventos tipado**: cada evento tiene su payload, y TS no te deja emitir o escuchar con datos incorrectos.

## Los eventos

Se describen con un mapa de nombre → payload:

```ts
type EventosApp = {
  login: { usuario: string }
  logout: undefined
  error: { codigo: number; mensaje: string }
}
```

## Parte 1: la clase Emisor

```ts
class Emisor<E extends Record<string, unknown>> {
  on<K extends keyof E & string>(evento: K, fn: (payload: E[K]) => void): () => void
  emit<K extends keyof E & string>(evento: K, payload: E[K]): void
}
```

- `on` registra un listener y devuelve una función para quitarlo.
- `emit` llama a todos los listeners de ese evento, en orden de registro.

```ts
const app = new Emisor<EventosApp>()
app.on('login', (p) => p.usuario.toUpperCase()) // p: { usuario: string }
app.emit('error', { codigo: 500, mensaje: 'x' })
app.emit('login', { usuario: 1 })                // Error de tipo
```

Internamente puedes usar un `Map<string, Set<(payload: any) => void>>`. Dentro de la implementación un `any` controlado está bien: la API pública es lo que está tipado.

## Parte 2: handlers con template literals

Define dos tipos:

```ts
type NombreHandler<K extends string> = `on${Capitalize<K>}`
// NombreHandler<'login'> = 'onLogin'

type Handlers<E> = {
  [K in keyof E & string as NombreHandler<K>]?: (payload: E[K]) => void
}
// Handlers<EventosApp> = { onLogin?: ...; onLogout?: ...; onError?: ... }
```

E implementa `conectar(emisor, handlers)`: registra cada handler presente en su evento (`onLogin` → `'login'`) y devuelve **una** función que los desconecta todos.

```ts
const desconectar = conectar(app, {
  onLogin: (p) => console.log(p.usuario),
  onError: (e) => console.log(e.codigo),
})
```

Para pasar de `'onLogin'` a `'login'` en runtime: quita `'on'` y pasa la primera letra a minúscula.

Este patrón (props `onAlgo` derivadas de nombres de eventos) es justo lo que verás en React.
