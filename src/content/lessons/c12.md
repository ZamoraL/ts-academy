El "error del billón de dólares": usar un valor que resulta ser `null` o `undefined`. TS lo ataca con **`strictNullChecks`** (incluido en `strict`).

## Sin strictNullChecks

`null` y `undefined` se pueden asignar a cualquier tipo, y TS no te avisa:

```ts
let nombre: string = null // permitido 😱
nombre.length             // crash en runtime
```

## Con strictNullChecks

`null` y `undefined` son tipos **propios**. Si un valor puede faltar, tiene que decirlo en su tipo:

```ts
let nombre: string = null
// Error: Type 'null' is not assignable to type 'string'.

let apodo: string | null = null // ✓ explícito
```

Y antes de usarlo, tienes que comprobarlo:

```ts
function saludar(nombre: string | null) {
  console.log(nombre.toUpperCase())
  // Error: 'nombre' is possibly 'null'.

  if (nombre === null) return
  console.log(nombre.toUpperCase()) // ✓ aquí nombre: string
}
```

## Dónde aparecen

Muchas APIs devuelven `null` o `undefined` cuando no encuentran algo, y TS lo refleja:

```ts
const n = [1, 2, 3].find((x) => x > 5)           // number | undefined
const el = document.querySelector('#app')        // Element | null
const v = localStorage.getItem('clave')           // string | null
const m = new Map<string, number>().get('a')      // number | undefined
```

## Formas de manejarlo

```ts
// 1. guard clause
if (!el) throw new Error('No existe #app')
el.innerHTML = 'hola' // el: Element

// 2. optional chaining
const largo = v?.length // number | undefined

// 3. valor por defecto
const valor = v ?? 'por defecto' // string

// 4. comprobación
if (n !== undefined) console.log(n.toFixed(1))
```

## Opcional vs `| undefined`

```ts
interface A { x?: number }            // puede omitirse
interface B { x: number | undefined } // debe estar, aunque valga undefined

const a: A = {}  // ✓
const b: B = {}  // Error: Property 'x' is missing
```

## null o undefined, ¿cuál uso?

En código propio, elige uno y sé consistente. Muchos equipos usan `undefined` para "no hay valor" (es lo que devuelven `find`, las propiedades opcionales y los parámetros omitidos) y reservan `null` para cuando una API lo exige.
