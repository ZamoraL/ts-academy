## Extender interfaces

`extends` copia las propiedades de otra interfaz y añade las suyas:

```ts
interface DireccionBasica {
  calle: string
  ciudad: string
  cp: string
}

interface DireccionConDepto extends DireccionBasica {
  depto: string
}
```

Se puede extender de **varias** a la vez:

```ts
interface Coloreable { color: string }
interface Circulo { radio: number }

interface CirculoColoreable extends Coloreable, Circulo {}

const cc: CirculoColoreable = { color: 'rojo', radio: 4 }
```

## Intersecciones: `&`

Combinan tipos existentes en uno que tiene **todo** de ambos:

```ts
type CirculoColoreable = Coloreable & Circulo
```

Útil para combinar sobre la marcha:

```ts
function dibujar(c: Coloreable & Circulo) {
  console.log(`Color ${c.color}, radio ${c.radio}`)
}
```

## extends vs &

Casi equivalentes, con una diferencia: cómo manejan **conflictos**.

```ts
interface A { x: string }
interface B extends A { x: number }
// Error: Interface 'B' incorrectly extends interface 'A'. Types of property 'x' are incompatible.

type C = { x: string } & { x: number }
// Sin error... pero x es string & number = never
```

`extends` te avisa en la declaración; `&` produce silenciosamente un tipo imposible. Por eso, para jerarquías, `extends` da errores más claros.

## Componer en lugar de repetir

```ts
interface ConId { id: number }
interface ConFechas { creado: Date; actualizado: Date }

interface Usuario extends ConId, ConFechas {
  email: string
}
interface Pedido extends ConId, ConFechas {
  total: number
}
```

## Unión vs intersección

Es fácil confundirlas:

| | `A \| B` | `A & B` |
|---|---|---|
| Valor | **uno de** A o B | **ambos** a la vez |
| Propiedades accesibles sin narrowing | solo las comunes | todas |

```ts
type U = { a: 1 } | { b: 2 }
type I = { a: 1 } & { b: 2 }

const u: U = { a: 1 }        // ✓
const i: I = { a: 1, b: 2 }  // ✓ necesita las dos
```
