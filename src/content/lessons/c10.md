Para no repetir tipos, dales un **nombre**.

## type alias

```ts
type Punto = {
  x: number
  y: number
}

type Id = number | string

function imprimirCoord(p: Punto) { }
function buscar(id: Id) { }
```

Un `type` puede nombrar **cualquier** tipo: objetos, uniones, primitivos, funciones...

## interface

Otra forma de nombrar **tipos de objeto**:

```ts
interface Punto {
  x: number
  y: number
}
```

Para objetos, funcionan casi igual. TS compara por **forma**, no por nombre (*structural typing*):

```ts
interface Punto { x: number; y: number }
type Coord = { x: number; y: number }

const p: Punto = { x: 1, y: 2 }
const c: Coord = p // ✓ misma forma, mismo tipo en la práctica
```

## Diferencias

### Extender

```ts
interface Animal {
  nombre: string
}
interface Oso extends Animal {
  miel: boolean
}

// con type, usando intersección (&)
type Animal2 = { nombre: string }
type Oso2 = Animal2 & { miel: boolean }
```

### Reabrir

Una `interface` se puede declarar varias veces y se **fusiona**; un `type` no:

```ts
interface Ventana { titulo: string }
interface Ventana { ancho: number }
// Ventana tiene titulo y ancho

type Caja = { a: string }
type Caja = { b: string }
// Error: Duplicate identifier 'Caja'.
```

### Solo type puede...

```ts
type Estado = 'activo' | 'inactivo'   // uniones
type Par = [string, number]           // tuplas
type Fn = (x: number) => string       // funciones (interface también puede, más verboso)
```

## ¿Cuál uso?

El Handbook recomienda: **usa `interface` hasta que necesites algo que solo `type` puede hacer**. Muchos equipos usan `type` para todo por consistencia. Ambas opciones son correctas; lo importante es ser consistente en un proyecto.

## Convenciones

- Nombres en `PascalCase`: `Usuario`, `RespuestaApi`.
- Sin prefijo `I` (`IUsuario`): es un estilo antiguo de otros lenguajes.
