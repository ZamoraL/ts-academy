## Tipos de objeto

Describe las propiedades y su tipo, separadas por `;` o `,`:

```ts
function imprimirCoord(punto: { x: number; y: number }) {
  console.log(`(${punto.x}, ${punto.y})`)
}

imprimirCoord({ x: 3, y: 7 })
imprimirCoord({ x: 3 })
// Error: Property 'y' is missing in type '{ x: number; }' but required in type '{ x: number; y: number; }'.
```

## Propiedades opcionales: `?`

```ts
function imprimirNombre(obj: { nombre: string; apellido?: string }) {
  // ...
}
imprimirNombre({ nombre: 'Ada' })                     // ✓
imprimirNombre({ nombre: 'Ada', apellido: 'Lovelace' }) // ✓
```

Una propiedad opcional puede ser `undefined`, así que **TS te obliga a comprobarla** antes de usarla:

```ts
function imprimirNombre(obj: { nombre: string; apellido?: string }) {
  console.log(obj.apellido.toUpperCase())
  // Error: 'obj.apellido' is possibly 'undefined'.

  if (obj.apellido !== undefined) {
    console.log(obj.apellido.toUpperCase()) // ✓
  }

  console.log(obj.apellido?.toUpperCase()) // ✓ también
}
```

Aquí ves por qué aprendiste `?.` y `??` en el bloque B.

## Comprobación de propiedades extra

Con un **objeto literal**, TS se queja de propiedades que el tipo no declara:

```ts
imprimirCoord({ x: 1, y: 2, z: 3 })
// Error: Object literal may only specify known properties, and 'z' does not exist in type ...
```

Así detecta typos como `{ nombr: 'Ada' }`.

## Inferencia de objetos

```ts
const usuario = { nombre: 'Ada', edad: 36 }
// const usuario: { nombre: string; edad: number }

usuario.edad = '37'
// Error: Type 'string' is not assignable to type 'number'.
usuario.email = 'a@x.com'
// Error: Property 'email' does not exist on type ...
```

TS fija la forma del objeto al crearlo. Si una propiedad aparecerá después, decláralo en el tipo como opcional.

## Escribir el mismo tipo muchas veces

Repetir `{ x: number; y: number }` en cada función es tedioso. En dos unidades verás cómo darle nombre con `type` e `interface`.
