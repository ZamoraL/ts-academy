## Inferencia

En la mayoría de los casos, TS infiere el tipo del valor inicial:

```tsx
const [contador, setContador] = useState(0)       // number
const [nombre, setNombre] = useState('')          // string
const [abierto, setAbierto] = useState(false)     // boolean

setContador('uno') // Error: Argument of type 'string' is not assignable...
```

## Cuando el inicial no basta: el genérico

`useState` es una función genérica: `useState<T>(inicial: T)`. Indica `T` cuando el valor inicial no describe todos los valores posibles.

### null mientras carga

```tsx
interface Usuario { id: number; nombre: string }

const [usuario, setUsuario] = useState<Usuario | null>(null)

usuario.nombre   // Error: 'usuario' is possibly 'null'.
usuario?.nombre  // ✓
```

Sin el genérico, `useState(null)` tendría tipo `null` para siempre.

### Arrays vacíos

```tsx
const [tareas, setTareas] = useState([])           // never[] 😕
const [tareas, setTareas] = useState<Tarea[]>([])  // ✓
```

### Uniones de literales

```tsx
type Filtro = 'todas' | 'pendientes' | 'hechas'
const [filtro, setFiltro] = useState<Filtro>('todas')
// sin el genérico sería string, y setFiltro('cualquiercosa') compilaría
```

## Estado con forma de objeto

```tsx
interface Formulario { email: string; mensaje: string }

const [form, setForm] = useState<Formulario>({ email: '', mensaje: '' })

setForm({ ...form, email: 'a@b.c' }) // ✓
setForm({ email: 'a@b.c' })          // Error: Property 'mensaje' is missing
```

Para actualizar un campo genéricamente, con `keyof`:

```tsx
function actualizar<K extends keyof Formulario>(campo: K, valor: Formulario[K]) {
  setForm((f) => ({ ...f, [campo]: valor }))
}
```

## Estados imposibles

Evita varios booleans que pueden contradecirse:

```tsx
// ❌ ¿cargando y con error a la vez?
const [cargando, setCargando] = useState(false)
const [error, setError] = useState<string | null>(null)
const [datos, setDatos] = useState<Datos | null>(null)

// ✅ una unión discriminada
type Estado =
  | { tipo: 'inactivo' }
  | { tipo: 'cargando' }
  | { tipo: 'error'; mensaje: string }
  | { tipo: 'ok'; datos: Datos }

const [estado, setEstado] = useState<Estado>({ tipo: 'inactivo' })
```

Con `if (estado.tipo === 'ok')`, TS sabe que `estado.datos` existe. Es el mismo patrón que tu máquina de estados del bloque D.

## El tipo del setter

Si pasas un setter como prop:

```tsx
import type { Dispatch, SetStateAction } from 'react'

interface Props {
  setFiltro: Dispatch<SetStateAction<Filtro>>
}
```

Aunque normalmente es mejor pasar un callback con nombre de dominio: `onCambiarFiltro: (f: Filtro) => void`.
