Para mostrar una lista, transforma un array de datos en un array de elementos JSX con **`map`**.

```jsx
const personas = ['Ada', 'Grace', 'Alan']

function Lista() {
  return (
    <ul>
      {personas.map((p) => (
        <li key={p}>{p}</li>
      ))}
    </ul>
  )
}
```

React sabe renderizar arrays de elementos.

## Filtrar antes de mostrar

```jsx
const quimicos = personas.filter((p) => p.profesion === 'química')

<ul>
  {quimicos.map((p) => (
    <li key={p.id}>{p.nombre}</li>
  ))}
</ul>
```

Todo lo que aprendiste en el bloque A (`map`, `filter`, `toSorted`...) se usa aquí constantemente.

## key

Cada elemento de una lista necesita una prop **`key`** única entre sus hermanos:

```jsx
{tareas.map((t) => (
  <Tarea key={t.id} tarea={t} />
))}
```

¿Por qué? Cuando la lista cambia (se añade, borra o reordena algo), React usa la `key` para saber **qué elemento es cuál** y conservar su estado. Sin ella, React avisa en consola.

### Qué usar como key

- ✅ Un id estable que viene de los datos (`t.id`, un id de la base de datos).
- ⚠️ El índice (`(t, i) => <li key={i}>`): solo si la lista nunca se reordena ni se filtra. Si no, causa bugs sutiles.
- ❌ `Math.random()`: cambia en cada render, React recrea todo.

La `key` no llega como prop al componente: si la necesitas dentro, pásala aparte (`id={t.id}`).

## Extraer el elemento a un componente

Cuando cada elemento tiene su propia estructura:

```jsx
function TarjetaPersona({ persona }) {
  return (
    <li>
      <strong>{persona.nombre}</strong>: {persona.profesion}
    </li>
  )
}

<ul>
  {personas.map((p) => (
    <TarjetaPersona key={p.id} persona={p} />
  ))}
</ul>
```

La `key` va en el elemento que devuelve el `map`, no dentro del componente.

## Lista vacía

```jsx
{tareas.length === 0 ? <p>No hay tareas</p> : <ul>{...}</ul>}
```
