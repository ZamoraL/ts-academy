**Narrowing** (estrechamiento) es cómo TS pasa de un tipo amplio, como `string | number`, a uno más concreto dentro de un bloque de código. Lo hace siguiendo tus comprobaciones.

## El ejemplo del Handbook

```ts
function padLeft(padding: number | string, input: string): string {
  return ' '.repeat(padding) + input
  // Error: Argument of type 'string | number' is not assignable to parameter of type 'number'.
}
```

`repeat` necesita un número, pero `padding` puede ser string. Comprobémoslo:

```ts
function padLeft(padding: number | string, input: string): string {
  if (typeof padding === 'number') {
    return ' '.repeat(padding) + input // padding: number
  }
  return padding + input               // padding: string
}
```

Pasa el ratón sobre `padding` en cada rama: el tipo cambia. Esa comprobación `typeof padding === 'number'` se llama **type guard**.

## Qué devuelve typeof

TS entiende estos valores de `typeof`:

`'string'` · `'number'` · `'bigint'` · `'boolean'` · `'symbol'` · `'undefined'` · `'object'` · `'function'`

## La trampa de 'object'

¿Recuerdas que `typeof null === 'object'`? TS también lo sabe:

```ts
function imprimirTodos(strs: string | string[] | null) {
  if (typeof strs === 'object') {
    for (const s of strs) {
    // Error: 'strs' is possibly 'null'.
      console.log(s)
    }
  }
}
```

Dentro del `if`, `strs` es `string[] | null`. Lo resolverás en la siguiente unidad.

## Funciona con else y con return

```ts
function describir(x: string | number | boolean) {
  if (typeof x === 'string') return `texto: ${x}`
  // aquí x: number | boolean
  if (typeof x === 'number') return `número: ${x}`
  // aquí x: boolean
  return x ? 'sí' : 'no'
}
```

TS va **restando** posibilidades a medida que descartas casos. Este estilo con `return` temprano es el más legible.
