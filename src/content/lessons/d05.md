A veces la comprobación es compleja y quieres ponerla en una función. Pero TS no "ve" dentro de una función normal que devuelve `boolean`:

```ts
function esPez(animal: Pez | Ave): boolean {
  return 'nadar' in animal
}

if (esPez(mascota)) {
  mascota.nadar()
  // Error: Property 'nadar' does not exist on type 'Pez | Ave'.
}
```

## Type predicates: `x is T`

Cambia el tipo de retorno por un **predicado de tipo**:

```ts
function esPez(animal: Pez | Ave): animal is Pez {
  return 'nadar' in animal
}

if (esPez(mascota)) {
  mascota.nadar() // mascota: Pez
} else {
  mascota.volar() // mascota: Ave
}
```

`animal is Pez` significa: "si esta función devuelve `true`, `animal` es un `Pez`".

## Con filter

El uso más práctico. `filter` acepta un predicado y **estrecha el tipo del array resultante**:

```ts
const zoo: (Pez | Ave)[] = [...]

const peces1 = zoo.filter((a) => 'nadar' in a) // (Pez | Ave)[]  😕
const peces2 = zoo.filter(esPez)               // Pez[]          ✓
```

Muy común para quitar `undefined` de un array:

```ts
const valores = [1, undefined, 3]           // (number | undefined)[]

const definidos = valores.filter(
  (v): v is number => v !== undefined,
)                                           // number[]
```

> TypeScript 5.5 empezó a inferir algunos predicados automáticamente. El editor de esta app usa TS 5.4, así que escríbelos a mano: es bueno saber hacerlo.

## Validar datos desconocidos

Los predicados brillan con `unknown`:

```ts
interface Usuario { nombre: string; edad: number }

function esUsuario(x: unknown): x is Usuario {
  return (
    typeof x === 'object' &&
    x !== null &&
    'nombre' in x && typeof x.nombre === 'string' &&
    'edad' in x && typeof x.edad === 'number'
  )
}

const datos: unknown = JSON.parse(texto)
if (esUsuario(datos)) {
  datos.nombre // ✓
}
```

## Responsabilidad

TS **confía** en tu predicado. Si la implementación está mal (devuelve `true` para algo que no es un `Pez`), el tipo mentirá. Un predicado es como una assertion: mantenlo simple y correcto.
