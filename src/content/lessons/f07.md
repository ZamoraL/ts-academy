Proyecto final de los bloques de TypeScript: una **mini librería de validación** de datos, con la misma idea que [Zod](https://zod.dev) (que usarás en el bloque H).

## El problema que resuelve

TS no valida en runtime. Los datos que vienen de una API o de `JSON.parse` son `unknown`. Con un *schema* describes la forma **una vez** y obtienes dos cosas:

1. Una función que valida en runtime.
2. El tipo de TypeScript, **inferido** del schema.

```ts
const UsuarioSchema = objeto({
  nombre: texto(),
  edad: numero(),
  etiquetas: lista(texto()),
  apodo: opcional(texto()),
})

type Usuario = Infer<typeof UsuarioSchema>
// { nombre: string; edad: number; etiquetas: string[]; apodo: string | undefined }

const u = UsuarioSchema.parse(JSON.parse(texto)) // u: Usuario, o lanza un error
```

## Qué implementar (y exportar)

```ts
export interface Schema<T> {
  parse(valor: unknown): T
}

export type Infer<S> = S extends Schema<infer T> ? T : never
```

Funciones que crean schemas:

| Función | Tipo resultante | Error si no cumple |
|---|---|---|
| `texto()` | `Schema<string>` | `'Se esperaba texto'` |
| `numero()` | `Schema<number>` (rechaza `NaN`) | `'Se esperaba número'` |
| `booleano()` | `Schema<boolean>` | `'Se esperaba booleano'` |
| `lista(item)` | `Schema<T[]>` | `'Se esperaba lista'`; si falla un elemento: `'[i]: <error>'` |
| `opcional(s)` | `Schema<T \| undefined>` | acepta `undefined`, si no delega en `s` |
| `objeto(forma)` | `Schema<{ [K in keyof F]: Infer<F[K]> }>` | `'Se esperaba objeto'`; si falla un campo: `'<campo>: <error>'` |

Los errores anidados se componen: un fallo en `etiquetas[1]` dentro de un objeto da `'etiquetas: [1]: Se esperaba texto'`.

## Lo que practicas

Todo el bloque E en un solo archivo: genéricos, restricciones, `infer`, mapped types, conditional types, `unknown` con narrowing, módulos con `export`… y el patrón que usan las librerías reales.

## Pista para objeto

```ts
export function objeto<F extends Record<string, Schema<unknown>>>(forma: F): Schema<{ [K in keyof F]: Infer<F[K]> }>
```

Dentro de `parse`, recorre `Object.keys(forma)`, valida cada campo con `try/catch` para añadir el prefijo al mensaje, y construye el resultado. Al final necesitarás un `as` para decirle a TS que el objeto construido tiene el tipo inferido: es uno de los pocos casos legítimos.
