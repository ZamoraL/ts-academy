`infer` permite **extraer** un tipo de dentro de otro, dentro de un conditional type.

## El problema

Quieres el tipo de los elementos de un array:

```ts
type Elemento<T> = T extends any[] ? T[number] : T
```

Funciona, pero `infer` lo dice de forma más directa:

```ts
type Elemento<T> = T extends (infer E)[] ? E : T

type A = Elemento<string[]> // string
type B = Elemento<number>   // number
```

Se lee: "si `T` es un array de *algo*, llama a ese algo `E` y devuélvelo".

## Retorno de una función

Así está definido `ReturnType` en la librería estándar (simplificado):

```ts
type MiReturnType<T> = T extends (...args: any[]) => infer R ? R : never

type R1 = MiReturnType<() => string>               // string
type R2 = MiReturnType<(x: number) => boolean[]>   // boolean[]
type R3 = MiReturnType<string>                     // never
```

## Parámetros

```ts
type MisParametros<T> = T extends (...args: infer P) => any ? P : never

type P = MisParametros<(a: string, b: number) => void> // [a: string, b: number]

type Primero<T> = T extends (primero: infer A, ...resto: any[]) => any ? A : never
type F = Primero<(id: number, nombre: string) => void> // number
```

## Promesas

```ts
type Desenvolver<T> = T extends Promise<infer V> ? V : T

type D = Desenvolver<Promise<string>> // string
```

La librería estándar tiene `Awaited<T>`, que además desenvuelve promesas anidadas.

## Strings (con template literal types)

```ts
type SinPrefijo<T> = T extends `on${infer Resto}` ? Resto : T

type E = SinPrefijo<'onClick'> // 'Click'
```

Lo verás en la unidad de template literal types.

## Tuplas

```ts
type Primero<T> = T extends [infer A, ...unknown[]] ? A : never
type Ultimo<T> = T extends [...unknown[], infer Z] ? Z : never

type U = Ultimo<[1, 2, 3]> // 3
```

## Restringir lo inferido

```ts
type PrimerString<T> = T extends [infer S extends string, ...unknown[]] ? S : never

type A = PrimerString<['a', 1]> // 'a'
type B = PrimerString<[1, 'a']> // never
```
