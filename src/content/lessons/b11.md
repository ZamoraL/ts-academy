Una **promesa** representa un valor que estará disponible **en el futuro**. Tiene tres estados:

- **pending**: todavía esperando.
- **fulfilled**: terminó bien, con un valor.
- **rejected**: falló, con un error.

## Consumir una promesa

```js
fetch('https://api.example.com/usuarios/1')
  .then((respuesta) => respuesta.json())
  .then((usuario) => console.log(usuario.nombre))
  .catch((error) => console.log('Falló:', error.message))
  .finally(() => console.log('Terminado'))
```

- `.then(fn)` se ejecuta cuando se cumple. Lo que devuelve `fn` pasa al siguiente `.then`.
- Si `fn` devuelve otra promesa, la cadena **espera** a que se resuelva.
- `.catch(fn)` atrapa un error en **cualquier** paso anterior.

Compara con el callback hell: la cadena es plana.

## Crear una promesa

```js
function esperar(ms) {
  return new Promise((resolve) => {
    setTimeout(resolve, ms)
  })
}

esperar(1000).then(() => console.log('pasó 1 s'))
```

```js
function dividir(a, b) {
  return new Promise((resolve, reject) => {
    if (b === 0) reject(new Error('División entre 0'))
    else resolve(a / b)
  })
}
```

Atajos: `Promise.resolve(valor)` y `Promise.reject(error)`.

## Varias a la vez

```js
// espera a todas; falla si una falla
const [a, b] = await Promise.all([cargarA(), cargarB()])

// espera a todas, sin fallar
Promise.allSettled([...]) // [{ status: 'fulfilled', value }, { status: 'rejected', reason }]

// la primera que termine
Promise.race([...])
```

`Promise.all` es clave para rendimiento: lanza las peticiones **en paralelo** en lugar de una tras otra.

## Las promesas también usan la cola

```js
console.log('A')
Promise.resolve().then(() => console.log('B'))
console.log('C')
// A, C, B
```

El `.then` siempre corre **después** del código síncrono actual.
