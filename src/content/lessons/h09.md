Un componente también puede ser **genérico**: muy útil para listas, tablas, selects... que funcionan con cualquier tipo de dato.

## El problema

```tsx
interface ListaProps {
  items: unknown[]
  renderItem: (item: unknown) => ReactNode
}
```

Con `unknown`, quien usa la lista no tiene autocompletado en `renderItem`, y tiene que hacer comprobaciones o assertions.

## Componente genérico

```tsx
interface ListaProps<T> {
  items: T[]
  renderItem: (item: T) => ReactNode
  getKey: (item: T) => string | number
}

function Lista<T>({ items, renderItem, getKey }: ListaProps<T>) {
  return (
    <ul>
      {items.map((item) => (
        <li key={getKey(item)}>{renderItem(item)}</li>
      ))}
    </ul>
  )
}
```

Al usarlo, TS **infiere** `T` a partir de `items`:

```tsx
<Lista
  items={usuarios}                         // T = Usuario
  getKey={(u) => u.id}                     // u: Usuario
  renderItem={(u) => <b>{u.nombre}</b>}    // u: Usuario, autocompletado
/>
```

## En archivos .tsx con funciones flecha

`<T>` se confunde con una etiqueta JSX. Truco:

```tsx
const Lista = <T,>(props: ListaProps<T>) => { ... } // la coma desambigua
```

Con `function` no hay problema.

## Restricciones

```tsx
interface ConId { id: string | number }

function Tabla<T extends ConId>({ filas, columnas }: TablaProps<T>) {
  // aquí puedes usar fila.id como key sin pedir getKey
}
```

## Ejemplo: Select tipado

```tsx
interface SelectProps<T extends string> {
  opciones: readonly T[]
  valor: NoInfer<T>          // T se deduce solo de opciones
  onCambiar: (valor: T) => void
}

function Select<T extends string>({ opciones, valor, onCambiar }: SelectProps<T>) {
  return (
    <select value={valor} onChange={(e) => onCambiar(e.target.value as T)}>
      {opciones.map((o) => (
        <option key={o} value={o}>{o}</option>
      ))}
    </select>
  )
}

const TALLAS = ['S', 'M', 'L'] as const
const [talla, setTalla] = useState<(typeof TALLAS)[number]>('M')

<Select opciones={TALLAS} valor={talla} onCambiar={setTalla} />
<Select opciones={TALLAS} valor="XL" onCambiar={setTalla} /> // Error
```

Sin `NoInfer`, TS deduciría `T` también desde `valor`: `valor="XL"` ampliaría `T` a `'S' | 'M' | 'L' | 'XL'` en vez de dar error. `NoInfer<T>` (TS 5.4) le dice "no uses este sitio para inferir".

El `as T` en `onChange` es necesario porque el DOM siempre da `string`; es seguro porque solo hay opciones de tipo `T`.

## keyof en props

```tsx
interface TablaProps<T> {
  filas: T[]
  columnas: (keyof T)[]
}

<Tabla filas={usuarios} columnas={['nombre', 'email']} />
<Tabla filas={usuarios} columnas={['nombr']} /> // Error
```

Todo lo del bloque E, aplicado a componentes.
