Los **template literal types** usan la sintaxis de los template literals de JS, pero con **tipos**.

```ts
type Mundo = 'mundo'
type Saludo = `hola ${Mundo}` // 'hola mundo'
```

## Con uniones: todas las combinaciones

```ts
type Tamaño = 'sm' | 'md' | 'lg'
type Color = 'rojo' | 'azul'

type Clase = `btn-${Tamaño}-${Color}`
// 'btn-sm-rojo' | 'btn-sm-azul' | 'btn-md-rojo' | ... (6 en total)
```

## Con tipos primitivos

```ts
type Px = `${number}px`

const a: Px = '10px'   // ✓
const b: Px = '1.5px'  // ✓
const c: Px = '10em'   // Error

type Ruta = `/${string}`
const r: Ruta = '/usuarios' // ✓
const s: Ruta = 'usuarios'  // Error
```

## Manipulación de strings

Cuatro tipos intrínsecos:

```ts
Uppercase<'hola'>     // 'HOLA'
Lowercase<'HOLA'>     // 'hola'
Capitalize<'hola'>    // 'Hola'
Uncapitalize<'Hola'>  // 'hola'
```

## Ejemplo: eventos `on...`

```ts
type Evento = 'click' | 'focus' | 'blur'
type Handler = `on${Capitalize<Evento>}` // 'onClick' | 'onFocus' | 'onBlur'
```

Así se derivan las props de eventos de React a partir de nombres de eventos.

## Con infer: parsear strings

```ts
type ParamDeRuta<R> = R extends `${string}:${infer P}/${infer Resto}`
  ? P | ParamDeRuta<`/${Resto}`>
  : R extends `${string}:${infer P}`
    ? P
    : never

type P = ParamDeRuta<'/usuarios/:id/posts/:postId'> // 'id' | 'postId'
```

Así es como routers como React Router o Express tipan los parámetros de las URLs. (Es un tipo **recursivo**: se llama a sí mismo.)

## El ejemplo del Handbook: on con tipo

```ts
type ConEventos<T> = {
  on<K extends string & keyof T>(
    evento: `${K}Cambiado`,
    callback: (nuevo: T[K]) => void,
  ): void
}

declare function vigilar<T>(obj: T): T & ConEventos<T>

const persona = vigilar({ nombre: 'Ada', edad: 36 })
persona.on('edadCambiado', (n) => n.toFixed())  // n: number
persona.on('nombreCambiado', (s) => s.trim())   // s: string
persona.on('apellidoCambiado', () => {})        // Error
```

TS infiere `K` **desde dentro del string** `'edadCambiado'`.
