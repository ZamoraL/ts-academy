Las **props** son a los componentes lo que los parámetros a las funciones: datos que el padre le pasa al hijo.

## Pasar props

```jsx
<Avatar nombre="Ada" tamaño={64} />
```

- Strings con comillas.
- Cualquier otro valor entre llaves: números, booleans, objetos, arrays, funciones.

## Recibir props

El componente recibe **un objeto** con todas las props. Lo habitual es desestructurarlo:

```jsx
function Avatar({ nombre, tamaño }) {
  return (
    <img
      src={`/avatares/${nombre}.png`}
      alt={nombre}
      width={tamaño}
      height={tamaño}
    />
  )
}
```

### Valores por defecto

```jsx
function Avatar({ nombre, tamaño = 48 }) { ... }
```

## children

Lo que va **entre** las etiquetas de apertura y cierre llega como la prop especial `children`:

```jsx
function Tarjeta({ titulo, children }) {
  return (
    <section className="tarjeta">
      <h2>{titulo}</h2>
      {children}
    </section>
  )
}

<Tarjeta titulo="Perfil">
  <Avatar nombre="Ada" />
  <p>Matemática</p>
</Tarjeta>
```

Así se crean componentes "contenedores" reutilizables: layouts, modales, paneles.

## Las props son de solo lectura

Un componente **nunca** modifica sus props:

```jsx
function Mal({ contador }) {
  contador = contador + 1 // ❌ no hagas esto
}
```

Si algo tiene que cambiar, es **estado** (en unas unidades).

## Pasar todas las props

```jsx
function Perfil(props) {
  return <Avatar {...props} />
}
```

Útil a veces, pero con moderación: oculta qué props usa realmente el componente.

## Pensar en componentes

Una buena regla: si un trozo de interfaz se repite o tiene sentido por sí solo, conviértelo en un componente con props.
