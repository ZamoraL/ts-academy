Cuando algo sale mal, JavaScript **lanza** un error. Si nadie lo atrapa, el programa se detiene.

## try / catch

```js
try {
  const datos = JSON.parse('esto no es JSON')
} catch (error) {
  console.log('No se pudo leer:', error.message)
}
```

- El código en `try` se ejecuta normalmente.
- Si algo lanza un error, se salta directamente al `catch`.
- El programa continúa después del bloque.

## Lanzar tus propios errores

```js
function retirar(saldo, monto) {
  if (monto > saldo) {
    throw new Error('Saldo insuficiente')
  }
  return saldo - monto
}

try {
  retirar(100, 500)
} catch (e) {
  console.log(e.message) // 'Saldo insuficiente'
}
```

Lanza siempre `new Error(...)` (o una subclase), no strings: los `Error` incluyen el mensaje y la traza.

## finally

Se ejecuta **siempre**, haya error o no. Útil para limpiar:

```js
try {
  abrirConexion()
  hacerAlgo()
} catch (e) {
  console.log('falló')
} finally {
  cerrarConexion()
}
```

## Tipos de error comunes

| Error | Cuándo |
|---|---|
| `ReferenceError` | Usas una variable que no existe |
| `TypeError` | Usas un valor de forma incorrecta (`undefined.x`, llamar algo que no es función) |
| `SyntaxError` | El código está mal escrito |
| `RangeError` | Valor fuera de rango |

Muchos `TypeError` son exactamente los bugs que **TypeScript detecta antes de ejecutar**.

## ¿Cuándo usar try/catch?

Alrededor de operaciones que pueden fallar por causas externas: leer JSON, llamar a una API, acceder a almacenamiento. No lo uses para esconder bugs propios.
