**React** es una librería para construir interfaces de usuario a partir de **componentes**: piezas reutilizables que combinan estructura (HTML), lógica (JS) y, opcionalmente, estilo.

## El problema que resuelve

Con JavaScript puro, actualizar la página es manual:

```js
const boton = document.querySelector('#sumar')
const texto = document.querySelector('#contador')
let n = 0
boton.addEventListener('click', () => {
  n++
  texto.textContent = `Clics: ${n}` // tienes que acordarte de actualizar cada sitio
})
```

En una app grande, mantener el DOM sincronizado con los datos así se vuelve inmanejable.

## La idea de React

Describes **cómo debe verse la interfaz para un estado dado**, y React se encarga de actualizar el DOM cuando el estado cambia:

```jsx
function Contador() {
  const [n, setN] = useState(0)
  return <button onClick={() => setN(n + 1)}>Clics: {n}</button>
}
```

- No tocas el DOM: devuelves lo que quieres ver.
- Cuando `n` cambia, React vuelve a llamar a `Contador` y aplica solo las diferencias.

Esto se llama programación **declarativa**: describes el *qué*, no el *cómo*.

## Conceptos que verás en este bloque

| Concepto | Qué es |
|---|---|
| Componente | Una función que devuelve interfaz |
| JSX | La sintaxis tipo HTML dentro de JS |
| Props | Los "parámetros" de un componente |
| Estado | Datos que cambian y provocan un nuevo render |
| Eventos | Responder a clics, teclas, formularios |
| Efectos | Sincronizar con cosas externas (red, timers) |

## Cómo funcionan los ejercicios de React

A partir de aquí, cada ejercicio tiene una **vista previa**:

- **Ejecutar** renderiza tu componente (el que exportes con `export default`).
- **Comprobar** ejecuta tests que **interactúan** con tu componente: hacen clic en botones, escriben en inputs y comprueban el texto que aparece. Usan [Testing Library](https://testing-library.com), la herramienta estándar para probar componentes React.

Los ejercicios de este bloque son JavaScript con JSX (`.jsx`). En el bloque H pasarás a `.tsx`.
