## Chequeo estático

*Estático* significa **sin ejecutar el código**. TypeScript lee tu programa, deduce el tipo de cada valor y comprueba que lo uses de forma coherente.

```ts
const mensaje = 'hola'
mensaje()
// Error: This expression is not callable. Type 'String' has no call signatures.
```

En JavaScript esto fallaría solo al ejecutar la línea. TS lo detecta antes.

## Errores que no lanzan excepción

TS también detecta código que en JS **no falla** pero es casi seguro un bug:

```ts
const usuario = { nombre: 'Ada', edad: 36 }
usuario.ubicacion
// Error: Property 'ubicacion' does not exist on type '{ nombre: string; edad: number; }'.
```

En JS, eso devuelve `undefined` silenciosamente.

### Typos

```ts
const anuncio = 'Hola'
anuncio.toLocaleLowercase()
// Error: Property 'toLocaleLowercase' does not exist on type 'string'.
//        Did you mean 'toLocaleLowerCase'?
```

### Funciones sin llamar

```ts
function tirarMoneda() {
  return Math.random() < 0.5
}
if (tirarMoneda) { }
// Error: This condition will always return true since this function is always defined.
//        Did you mean to call it instead?
```

### Lógica imposible

```ts
const valor = Math.random() < 0.5 ? 'a' : 'b'
if (valor !== 'a') {
  // ...
} else if (valor === 'b') {
// Error: This comparison appears to be unintentional because the types '"a"' and '"b"' have no overlap.
}
```

TS sabe que en el `else`, `valor` solo puede ser `'a'`.

## Tipos como herramienta

El editor usa esta información para:

- autocompletar propiedades y métodos,
- mostrar el tipo al pasar el ratón,
- saltar a la definición,
- ofrecer arreglos rápidos ("quick fixes").

Muchos desarrolladores usan TS sobre todo por esto, más que por los errores.

## Lee los mensajes de error

Los mensajes de TS parecen largos, pero siguen un patrón: *"Type X is not assignable to type Y"* significa "esperaba Y y le diste X". Leerlos con calma es la habilidad más útil de este bloque.
