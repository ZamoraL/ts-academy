Un **conditional type** elige un tipo u otro según una condición. La sintaxis imita al ternario:

```ts
SomeType extends OtherType ? TrueType : FalseType
```

"Si `SomeType` es asignable a `OtherType`, el resultado es `TrueType`; si no, `FalseType`."

```ts
type EsString<T> = T extends string ? true : false

type A = EsString<'hola'> // true
type B = EsString<42>     // false
```

## Encadenar

```ts
type NombreTipo<T> =
  T extends string ? 'string' :
  T extends number ? 'number' :
  T extends boolean ? 'boolean' :
  T extends undefined ? 'undefined' :
  T extends Function ? 'function' :
  'object'

type T1 = NombreTipo<'a'>       // 'string'
type T2 = NombreTipo<() => void> // 'function'
```

## Para qué sirven

Con tipos concretos no aportan mucho (ya sabes la respuesta). Brillan con **genéricos**: el resultado depende del tipo que te pasen.

Ejemplo del Handbook: en vez de sobrecargas,

```ts
interface ConId { id: number }
interface ConNombre { nombre: string }

type IdONombre<T extends number | string> = T extends number ? ConId : ConNombre

declare function crearEtiqueta<T extends number | string>(x: T): IdONombre<T>

crearEtiqueta(1)       // ConId
crearEtiqueta('x')     // ConNombre
```

## Restringir dentro de la condición

En la rama verdadera, TS sabe que `T` cumple la condición:

```ts
type MensajeDe<T> = T extends { mensaje: unknown } ? T['mensaje'] : never

type M = MensajeDe<{ mensaje: string }> // string
type N = MensajeDe<{ otra: 1 }>         // never
```

Sin el `extends`, `T['mensaje']` sería un error.

## Ya existen muchos

Varios utility types de la librería estándar son conditional types:

```ts
type NonNullable<T> = T extends null | undefined ? never : T
type Extract<T, U> = T extends U ? T : never
type Exclude<T, U> = T extends U ? never : T
```

```ts
type A = NonNullable<string | null>        // string
type B = Exclude<'a' | 'b' | 'c', 'a'>    // 'b' | 'c'
```

¿Cómo funcionan con uniones? Lo verás en la unidad de tipos distributivos.

## Consejo

Los conditional types son potentes, pero los tipos complejos son difíciles de leer y depurar. Úsalos en utilidades reutilizables, no en cada rincón del código.
