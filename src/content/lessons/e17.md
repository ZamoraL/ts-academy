Vas a construir un **store de estado genérico**, parecido a lo que hacen librerías como Zustand (la que usa esta misma app para guardar tu progreso).

## La API

```ts
const store = crearStore({ contador: 0, usuario: null as string | null })

store.get()                      // { contador: 0, usuario: null }
store.select('contador')         // 0 (tipo number)
store.set({ contador: 1 })       // actualización parcial
store.set((s) => ({ contador: s.contador + 1 })) // a partir del estado actual
const desuscribir = store.subscribe((estado, anterior) => { ... })
desuscribir()
```

## Qué implementar

`crearStore<S extends object>(inicial: S)` devuelve un objeto de tipo `Store<S>`. Define también la interfaz:

```ts
interface Store<S> {
  get(): S
  select<K extends keyof S>(clave: K): S[K]
  set(cambio: Partial<S> | ((actual: S) => Partial<S>)): void
  subscribe(listener: (estado: S, anterior: S) => void): () => void
}
```

Reglas:

- `set` **no muta** el estado: crea uno nuevo con spread.
- Tras cada `set`, llama a todos los listeners con el estado nuevo y el anterior.
- `subscribe` devuelve una función que quita **ese** listener.
- Un listener que se desuscribe no vuelve a recibir llamadas.

## Lo que practicas

- Genéricos con restricción (`S extends object`).
- `keyof` e indexed access (`S[K]`).
- `Partial<S>`.
- Uniones de tipos de función (objeto o callback).
- Closures (el estado vive dentro de `crearStore`).

## Pista

Para distinguir si `cambio` es una función: `typeof cambio === 'function'`. TS estrechará la unión.
