## tsc: el compilador

TypeScript se instala como paquete de npm e incluye el comando `tsc`:

```bash
npm install --save-dev typescript
npx tsc hola.ts
```

`tsc` hace dos cosas:

1. **Comprueba los tipos** y muestra errores.
2. **Emite JavaScript**: genera `hola.js` borrando las anotaciones.

```ts
// hola.ts
function saludar(persona: string, fecha: Date) {
  console.log(`Hola ${persona}, hoy es ${fecha.toDateString()}`)
}
```

```js
// hola.js generado
function saludar(persona, fecha) {
  console.log(`Hola ${persona}, hoy es ${fecha.toDateString()}`)
}
```

Por defecto, `tsc` **emite aunque haya errores** (se puede cambiar con `noEmitOnError`).

## tsconfig.json

En un proyecto real no pasas archivos a mano: creas un `tsconfig.json` en la raíz y ejecutas solo `npx tsc`.

```json
{
  "compilerOptions": {
    "target": "es2022",
    "module": "esnext",
    "strict": true,
    "outDir": "dist",
    "noEmitOnError": true
  },
  "include": ["src"]
}
```

| Opción | Qué hace |
|---|---|
| `target` | Versión de JavaScript que se genera |
| `module` | Sistema de módulos de la salida |
| `strict` | Activa todas las comprobaciones estrictas (**siempre actívalo**) |
| `outDir` | Carpeta donde va el JS generado |
| `noEmitOnError` | No genera JS si hay errores |
| `include` | Qué archivos compilar |

`npx tsc --init` crea un `tsconfig.json` comentado con todas las opciones.

## strict

`strict: true` activa un grupo de opciones, entre ellas:

- `noImplicitAny`: error si TS no puede deducir un tipo.
- `strictNullChecks`: `null` y `undefined` no se pueden usar como si fueran otro tipo.

Las verás a fondo en este bloque. **Todos los ejercicios de esta app usan `strict`**.

## En proyectos con Vite o similar

Herramientas como Vite, Next.js o esbuild **transpilan** TS (borran los tipos) muy rápido, sin comprobarlos. La comprobación la hace el editor y un `tsc --noEmit` en el script de build. Así está montada esta misma app: mira su `package.json`, el script `build` ejecuta `tsc -b && vite build`.
