**Context** permite pasar datos a cualquier componente del árbol sin bajarlos prop por prop. Ideal para cosas "globales": el tema, el usuario autenticado, el idioma.

## Crear, proveer, consumir

```tsx
import { createContext, useContext, useState, type ReactNode } from 'react'

type Tema = 'claro' | 'oscuro'

// 1. Crear (con un valor por defecto)
const TemaContext = createContext<Tema>('claro')

// 2. Proveer
function App() {
  const [tema, setTema] = useState<Tema>('oscuro')
  return (
    <TemaContext value={tema}>
      <Pagina />
    </TemaContext>
  )
}

// 3. Consumir, en cualquier nivel debajo
function Boton() {
  const tema = useContext(TemaContext) // Tema
  return <button className={`btn-${tema}`}>OK</button>
}
```

En React 19 el contexto se usa directamente como proveedor (`<TemaContext value={...}>`). En versiones anteriores: `<TemaContext.Provider value={...}>`, que sigue funcionando.

## Contexto sin valor por defecto sensato

Muchas veces no hay un defecto razonable (¿qué usuario hay "por defecto"?). Patrón recomendado: `null` como defecto y un **hook propio** que comprueba:

```tsx
interface Sesion {
  usuario: string
  cerrar: () => void
}

const SesionContext = createContext<Sesion | null>(null)

export function useSesion(): Sesion {
  const sesion = useContext(SesionContext)
  if (!sesion) throw new Error('useSesion debe usarse dentro de <SesionProvider>')
  return sesion
}

export function SesionProvider({ children }: { children: ReactNode }) {
  const [usuario, setUsuario] = useState('Ada')
  return (
    <SesionContext value={{ usuario, cerrar: () => setUsuario('') }}>
      {children}
    </SesionContext>
  )
}
```

Ventajas:

- Quien consume recibe `Sesion`, no `Sesion | null`: sin comprobaciones repetidas.
- Si alguien olvida el proveedor, el error es claro e inmediato.
- El contexto en sí queda privado al módulo: solo se exportan el provider y el hook.

## Contexto + reducer

Patrón muy común para estado de toda la app:

```tsx
const TareasContext = createContext<{ tareas: Tarea[]; dispatch: Dispatch<Accion> } | null>(null)
```

## No abuses

- Si solo bajas una prop uno o dos niveles, pásala como prop: es más explícito.
- Cada cambio de valor re-renderiza **todos** los consumidores. Para estado que cambia muy a menudo, considera dividir contextos o una librería de estado (Zustand, como esta app).
