`"strict": true` es un interruptor que activa **varias** opciones. Conocerlas te ayuda a entender los errores y a migrar proyectos poco a poco.

## Lo que activa strict

| Opción | Qué comprueba |
|---|---|
| `noImplicitAny` | Error si TS tendría que usar `any` porque no puede inferir |
| `strictNullChecks` | `null`/`undefined` son tipos propios |
| `strictFunctionTypes` | Comprueba correctamente los parámetros de funciones pasadas como callback |
| `strictBindCallApply` | Tipa `fn.call`, `fn.apply`, `fn.bind` |
| `strictPropertyInitialization` | Los campos de clase deben inicializarse |
| `noImplicitThis` | Error si `this` sería `any` |
| `useUnknownInCatchVariables` | `catch (e)`: `e` es `unknown`, no `any` |
| `alwaysStrict` | Emite `"use strict"` en cada archivo |

Puedes activar `strict` y desactivar una concreta durante una migración:

```json
{ "strict": true, "strictPropertyInitialization": false }
```

## Opciones extra recomendadas (no incluidas en strict)

### noUncheckedIndexedAccess

Acceder por índice puede devolver `undefined`:

```ts
const nums = [1, 2, 3]
const x = nums[5]   // con la opción: number | undefined

const dic: Record<string, string> = {}
const v = dic.clave // string | undefined
```

Detecta muchos bugs reales, pero obliga a comprobar más.

### exactOptionalPropertyTypes

Distingue "la propiedad no está" de "está con valor `undefined`":

```ts
interface Opciones { tema?: 'claro' | 'oscuro' }
const o: Opciones = { tema: undefined } // Error con la opción
```

### noImplicitReturns

Todos los caminos de una función deben devolver algo si alguno lo hace.

### noFallthroughCasesInSwitch

Error si un `case` no vacío no termina en `break`/`return`.

### noUnusedLocals / noUnusedParameters

Errores por variables y parámetros sin usar. (Muchos equipos prefieren dejarlo a un linter.)

## El tsconfig de esta app

Mira `tsconfig.app.json` en el proyecto: verás `strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax` y `erasableSyntaxOnly`.

## Recomendación

En proyectos nuevos: `strict: true` desde el principio, siempre. Migrar después es mucho más caro.
