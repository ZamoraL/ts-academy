A veces un genérico no puede ser **cualquier** tipo: necesitas que tenga ciertas propiedades.

## El problema

```ts
function longitudes<T>(a: T, b: T) {
  return a.length + b.length
  // Error: Property 'length' does not exist on type 'T'.
}
```

TS no sabe nada de `T`: podría ser un número.

## extends: restringir

```ts
function masLargo<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b
}

masLargo('hola', 'adiós')     // string
masLargo([1, 2], [1, 2, 3])   // number[]
masLargo(10, 20)
// Error: Argument of type 'number' is not assignable to parameter of type '{ length: number; }'.
```

`T extends { length: number }` significa "T puede ser cualquier tipo, **siempre que** tenga `length: number`". Y como devuelve `T`, no `{ length: number }`, conservas el tipo exacto.

## Con interfaces

```ts
interface ConId {
  id: number
}

function porId<T extends ConId>(items: T[], id: number): T | undefined {
  return items.find((x) => x.id === id)
}

const u = porId(usuarios, 1) // Usuario | undefined, no ConId
```

## Restringir con otro parámetro: keyof

Ya lo viste con `keyof`:

```ts
function obtener<T, K extends keyof T>(obj: T, clave: K): T[K] {
  return obj[clave]
}
```

`K` está restringido a las claves de `T`. Un parámetro de tipo puede depender de otro.

## Restringir a primitivos

```ts
function unir<T extends string | number>(items: T[]): string {
  return items.join(', ')
}
```

## Un error común

```ts
function minimo<T extends { length: number }>(obj: T, min: number): T {
  if (obj.length >= min) return obj
  return { length: min }
  // Error: '{ length: number; }' is assignable to the constraint of type 'T',
  // but 'T' could be instantiated with a different subtype of constraint...
}
```

Si `T` es `string`, devolver `{ length: min }` no es un string. Prometer `T` significa devolver **exactamente** lo que te dieron (o algo derivado de ello), no cualquier cosa que cumpla la restricción.
